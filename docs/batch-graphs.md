## Runtime path

The [step cap](development.md#native-streaming-server) covers prefill and decode. C++ defaults to four lanes and a zero cap, selecting the legacy planner. With a positive cap, the ordinary planner rotates priority, budgets one row per ready lane, then assigns spare rows to MTP verification and finally prefill. Plain `advance` admits at most one prompt row per lane. A prefill tile fits up to 1,024 target-only text rows. Media and MTP tiles fit up to 128 rows. [Tensor-core prefix reuse](prefix-cache.md#tensor-core-scheduling) has its own planner. [Batch options](../include/sglang/decoder_batch.h#L49)<!-- prefix: "struct Decod" --> · [Planner](../src/decoder_batch.cpp#L251)<!-- prefix: "StepPlan pla" -->

`--trace-batches` reports `target_rows` and `step_budget`. The total charges executed prompt rows, including the first-output row, one row per ordinary decode lane, and computed target verification rows for MTP. Prefix restores, score-only full hits, draft seeding and proposals, commit replays, vision encoding, and emitted IDs stay outside the total. `prefill_rows` lists configured slots in order, with at least four entries. `width` counts selected lanes, including lanes assigned no rows. `decode` counts executed decode lanes. K0 reports `peak_request_bytes` on active steps. [Step trace](../apps/server/batch_service.cpp#L379)<!-- prefix: "std::cerr \u003c\u003c" -->

Batch execution defaults to eager. Add `--batch-cuda-graphs` to enable replay at any [server capacity](development.md#native-streaming-server). Use `--eager` to force eager execution when prefix reuse is off. Both [prefix prefill policies](prefix-cache.md#tensor-core-scheduling) support K0 decode replay. Steps that execute MTP work suppress K0 replay. Eligible [verification groups](mtp.md#target-verification-graph) use a separate executable. Each packed width first runs eagerly, then uses thread-local capture on the batch stream. Widths share scratch with fixed binding addresses. Each launch uploads tokens, positions, KV descriptors, KV and GDN pointers, and GQA score bindings. The page tables already reside on device. Replay runs embedding, decoder layers, and scoring. K0 can mix greedy, sampled, and [constrained requests](text-serving.md#finite-choice-constraints). Sampling and constrained selection follow replay on the same stream. The batch maps winners to logical slots and synchronizes before publication or retirement. ## Resident memory admission

The HTTP batch service sets a fixed request memory limit at startup. It takes the GPU memory free after model and batch initialization and reserves up to 2 GiB for shared allocations. At admission, it checks both the remaining limit after active requests and current free GPU memory after the same reserve. The [row and lane caps](development.md#native-streaming-server) apply separately. C++ batch callers can opt in with `DecoderBatchOptions::resident_memory_limit` in bytes. The effective limit is the smaller of that value and the startup limit. [HTTP setup](../apps/server/batch_service.cpp#L166)<!-- prefix: "batch = std:" --> · [C++ option](../include/sglang/decoder_batch.h#L54)<!-- prefix: "std::optiona" --> · [Startup limit](../src/decoder_batch.cpp#L330)<!-- prefix: "if (options." --> · [Admission check](../src/decoder_batch.cpp#L428)<!-- prefix: "std::size_t " -->

Each positive-budget request reserves page-rounded KV for the encoded or expanded prompt length plus the output budget minus one. The charge includes target KV, GDN state, workspace allowances, and any MTP draft KV, verifier, or media position storage. The resident path initializes request storage at admission and prepares shared sampling and constraint buffers when needed. A zero-budget request skips the reservation. [Charge calculation](../src/decoder_resources.cpp#L315)<!-- prefix: "std::size_t " --> · [Initialization](../src/decoder_batch.cpp#L469)<!-- prefix: "if (lane.res" --> · [Zero budget](../src/decoder_batch.cpp#L506)<!-- prefix: "if (options." -->

The batch can reduce a [chat request's implicit output budget](chat-serving.md#sampling-defaults-and-output-budget) to fit the fixed memory limit. It retains an explicit budget. If the resulting request exceeds the fixed limit, HTTP returns 413. If it fits the fixed limit but exceeds available capacity, HTTP returns 503. A CUDA allocation failure during initialization also returns 503 if cleanup succeeds. The service retires the failed lane and keeps active peers. These responses carry JSON before streaming starts. C++ callers receive `DecoderCapacityError` and can inspect `retryable`. A terminal CUDA status or a failed drain disables the batch. The service fails current jobs and reports [worker failure](http-server.md). An affected stream that has started sends an SSE error and ends without `[DONE]`. ## Constraints and failure behavior

Each batch caches one executable per eligible packed width from one through four. Sparse selections at those widths can replay in a wider service and rebind after retirement. A packed singleton can replay through 5,120 visible tokens, including the current token. Longer singletons use eager direct attention. Prefill and media work run eagerly. Decode wider than four runs eagerly and can use [long paged attention](long-paged-decode.md#runtime-path). Zero-budget lanes can finish outside the graph. A full prefix hit scores eagerly and stays out of the replay mask. Eligible peers can still replay. [Dispatch](../src/decoder_batch.cpp#L698)<!-- prefix: "const bool g" --> · [Singleton limit](../src/decoder_batch.cpp#L586)<!-- prefix: "if (count ==" --> · [Full hit](../src/decoder_batch.cpp#L661)<!-- prefix: "if (lane.res" --> · [Zero-budget completion](../src/decoder_batch.cpp#L905)<!-- prefix: "result.finis" -->

Ordered replay uses the slot's logits area at positions 0–5,119. In widths two through four, some later positions still require ordered replay. The first graph binding that needs those scores allocates storage for the request's page-rounded KV capacity. Each 128-position page needs 12,288 bytes for 24 FP32 scores per position. Capacity is at most 262,144 positions or 24 MiB of scores per lane. The kernels read the live position and score stride. The request keeps any allocated scores until retirement after stream completion. [Score binding](../src/decoder_batch.cpp#L611)<!-- prefix: "if (paged_de" --> · [Score allocation](../src/decoder_resources.cpp#L614)<!-- prefix: "ExactGqaWork" -->

If the first long-score allocation runs out of memory, the current step runs eager. That request remembers the failure and forces eager on later steps that need its long scores. Allocations already made for other lanes remain owned by those requests and can serve later replays. The executable remains available for other selections and recycled slots. Scratch OOM and recognized capture, instantiation, or synchronous launch rejections can disable one width. Before eager fallback, end capture, drain the stream, and destroy the graph handles. Other widths remain eligible. A target-only execution error outside graph fallback or [prefix recovery](prefix-cache.md#constraints-and-failure-behavior) disables the batch and fails current and subsequent requests. An invalid sampled or constrained selection retires only its lane. Cleanup retains resources while completion is uncertain. ### Page-parallel GQA decode

Singleton K0 decode can use page-parallel attention with 1,536–2,560 visible tokens, including the current token. Both prefill policies share decode. Serial eager and serial graph calls can use this path when they select exact attention. Serial graph exact attention requires page-rounded KV capacity of at most 5,120 tokens. [Row dispatch](../src/decoder_forward.cpp#L196)<!-- prefix: "cudaError_t " --> · [Serial graph attention](../src/mxfp8_gqa.cu#L902)<!-- prefix: "cudaError_t " -->

An eager batch step can use this path with one ordinary packed decode row and zero prefill rows. An independent full-prefix-hit score can run on that step. The width-one graph captures the same narrow and ordered attention routes. The live position selects the reduction inside its two attention nodes. The batch checks visible length before replay, so a request with KV capacity above 5,120 can still replay at shorter lengths. [Eager dispatch](../src/decoder_batch.cpp#L701)<!-- prefix: "work[0].narr" --> · [Bound attention](../src/decoder_forward.cpp#L265)<!-- prefix: "if (batch.si" --> · [Replay limit](../src/decoder_batch.cpp#L586)<!-- prefix: "if (count ==" -->

Each logical 128-token KV page produces an FP32 maximum, denominator, and value numerator per query head. The merge rescales both accumulators against the global maximum, divides, and rounds to BF16. This reduction order can change logits and greedy IDs. The path needs 495,360 bytes of the existing 496,640-byte logits allocation. Outside the window or with insufficient workspace, the exact path uses ordered replay. Every numerator in the tile must be finite. If a check fails, the tile recomputes QK scores for that head and replays the tokens in order. The fallback stays in the same graph node. It follows the ordered operator's numerical rules, which can also produce nonfinite output. ### Packed paged GQA decode

At packed widths two through four, graph replay selects split attention per lane. The window covers 8,192 through 16,384 visible tokens, including the current token. Each layer appends all bound lanes' KV, runs attention, and gates the outputs on the batch stream. The executable reads live positions and skips split and merge work for lanes outside the window. Its ordered score and replay nodes handle those lanes. Eager forwards with two to four rows group in-window ordinary decode lanes after KV append. Other eager rows at those widths follow the row dispatch, including direct attention beyond inline score capacity. Prefill and MTP verification keep their existing attention paths. [Bounds](../include/sglang/decoder_cuda.cuh#L95)<!-- prefix: "inline const" --> · [Bound forward](../src/decoder_forward.cpp#L248)<!-- prefix: "void attend_" --> · [Eager forward](../src/decoder_forward.cpp#L298)<!-- prefix: "void attend_" --> · [Bound fallback](../src/mxfp8_gqa.cu#L771)<!-- prefix: "__global__ v" -->

The split assigns 128-token KV pages to 16 partitions. It clamps the last to visible length. Bound width four and eager width four after compaction use a `(16, 12, 4)` grid with 256 threads per block. Blocks share decoded K and V between two adjacent query heads of one KV head. Split widths one through three use one block per query head and partition. [Split launch](../include/sglang/text/mxfp8_gqa_decode.cuh#L214)<!-- prefix: "void launch_" --> · [Paired split](../include/sglang/text/mxfp8_gqa_decode.cuh#L151)<!-- prefix: "__global__ v" -->

Four eight-thread subgroups per warp score four channel groups per pass. Two passes preserve each head's FP32 score tree and ascending group sum. Eight warps accumulate values in the original FMA order. Each head writes separate FP32 partials. The merge rescales the weight sum and value numerator to the global maximum, divides in FP32, and rounds to BF16. Split and ordered attention can produce different logits. Each lane uses 399,360 of its 496,640 logits bytes for 16-byte-aligned partials. In-window lanes skip request-owned score binding. [Paired scores](../include/sglang/text/mxfp8_gqa_decode.cuh#L48)<!-- prefix: "__device__ v" --> · [Merge](../src/mxfp8_gqa.cu#L656)<!-- prefix: "__global__ v" --> · [Scratch alias](../src/decoder_forward.cpp#L243)<!-- prefix: "PagedDecodeB" -->

A nonfinite visible score, visible V scale byte above 160, or invalid partial or merged result triggers FP64 replay for that query head. The merge requires finite numerators and BF16 outputs and a finite positive weight sum. Replay widens the decoded FP32 KV, processes the visible sequence in order, and rounds to BF16. Other heads keep their results. The captured sequence includes both FP64 head replay and ordered lane fallback.
