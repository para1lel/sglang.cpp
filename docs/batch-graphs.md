## Runtime path

The [step cap](development.md#native-streaming-server) covers prefill and decode. C++ defaults to four lanes and a zero cap, which selects legacy planning. A positive cap rotates priority, budgets one row per ready lane, and assigns spare rows to MTP verification before prefill. Plain `advance` admits at most one prompt row per lane. Prefill tiles cap at 1,024 text rows, 2,048 with [eligible SM100 prefill](flash-prefill.md#runtime-path), or 128 with media or MTP. [Tensor-core prefix reuse](prefix-cache.md#tensor-core-scheduling) has its own planner. `--trace-batches` reports `target_rows` and `step_budget`. The total charges executed prompt rows, including the first-output row, one row per ordinary decode lane, and computed target verification rows for MTP. ## Resident memory admission

The HTTP batch service sets a fixed request memory limit at startup. It takes the GPU memory free after model and batch initialization and reserves up to 2 GiB for shared allocations. At admission, it checks both the remaining limit after active requests and current free GPU memory after the same reserve. The [row and lane caps](development.md#native-streaming-server) apply separately. C++ batch callers can opt in with `DecoderBatchOptions::resident_memory_limit` in bytes. The effective limit is the smaller of that value and the startup limit. [HTTP setup](../apps/server/batch_service.cpp#L215)<!-- prefix: "batch = std:" --> · [C++ option](../include/sglang/decoder_batch.h#L55)<!-- prefix: "std::optiona" --> · [Startup limit](../src/decoder_batch.cpp#L333)<!-- prefix: "if (options." --> · [Admission check](../src/decoder_batch.cpp#L433)<!-- prefix: "std::size_t " -->

Each positive-budget request reserves page-rounded KV for the encoded or expanded prompt length plus the output budget minus one. The charge includes target KV, GDN state, workspace allowances, and any MTP draft KV, verifier, or media position storage. The resident path initializes request storage at admission and prepares shared sampling and constraint buffers when needed. A zero-budget request skips the reservation. [Charge calculation](../src/decoder_resources.cpp#L337)<!-- prefix: "std::size_t " --> · [Initialization](../src/decoder_batch.cpp#L474)<!-- prefix: "if (lane.res" --> · [Zero budget](../src/decoder_batch.cpp#L517)<!-- prefix: "if (options." -->

The batch can reduce a [chat request's implicit output budget](chat-serving.md#sampling-defaults-and-output-budget) to fit the fixed limit. It keeps explicit budgets. HTTP returns 413 above the fixed limit or 503 when current capacity is too low. A CUDA allocation failure during initialization returns 503 if cleanup succeeds. The service retires the failed lane and keeps active peers. These failures return JSON before [SSE opens on admission](http-server.md#completion-streams). C++ callers receive `DecoderCapacityError` with `retryable`. A terminal CUDA status or failed drain disables the batch. The service fails current jobs and reports [worker failure](http-server.md). An open writable stream sends an SSE error and ends without `[DONE]`. ## Constraints and failure behavior

Each batch caches at most one executable per packed bucket or narrow width. Sparse selections can rebind after retirement. Prefill and media run eagerly. Full prefix hits score eagerly outside the mask while eligible peers replay. [Packed graph](../src/text/decoder_graph_packed.cpp#L507)<!-- prefix: "const bool g" --> · [Full hit](../src/decoder_batch.cpp#L641)<!-- prefix: "if (lane.res" --> · [Zero-budget completion](../src/decoder_batch.cpp#L907)<!-- prefix: "result.finis" -->

Legacy ordered replay uses slot logits at positions 0–5,119. At widths 2–4, later ordered replay allocates scores for the request's page-rounded KV capacity on first use. Each 128-position page needs 12,288 bytes for 24 FP32 scores per position. Capacity is at most 262,144 positions or 24 MiB per lane. Kernels read the live position and stride. Requests retain scores until retirement after stream completion. [Score binding](../src/text/decoder_graph_packed.cpp#L436)<!-- prefix: "scores = req" --> · [Score allocation](../src/decoder_resources.cpp#L716)<!-- prefix: "ExactGqaWork" -->

First-use packed scratch allocation OOM permits legacy dispatch only after the CUDA error check and partial cleanup succeed. It disables packed decode for the batch's lifetime. Other setup errors propagate, including synchronization and cleanup failures. A terminal setup error disables the batch before legacy dispatch or decode publication. See [the fault regression](lessons.md#l009--terminal-error-during-first-packed-decode-setup). [Scratch allocation](../src/text/decoder_graph_packed.cpp#L140)<!-- prefix: "Element* Pac" --> · [Fallback](../src/text/decoder_graph_packed.cpp#L478)<!-- prefix: "PackedDecode" -->

Batch execution owns the winner pin and allocates it on first eligible use. Clean allocation OOM keeps per-lane reads for that batch. Other errors reach batch recovery. Cleanup frees the pin after stream drain and graph teardown. A rejected free retains ownership for device-local deferred reclamation. Terminal errors retain the resources. [Allocation](../src/decoder_resources.cpp#L435)<!-- prefix: "TextLogitCan" --> · [Release](../src/decoder_resources.cpp#L263)<!-- prefix: "CleanupError" --> · [Retry](../src/decoder_resources.cpp#L117)<!-- prefix: "static void " -->

Legacy long-score OOM forces eager for that step and later steps needing the failed request's scores. Other requests retain allocations, and recycled slots can replay. Width-local graph scratch OOM or eligible capture, instantiation, or synchronous launch rejection can disable one width. Before eager fallback, end capture, drain the stream, and destroy graph handles. Other widths remain eligible. A target-only execution error outside graph fallback or [prefix recovery](prefix-cache.md#constraints-and-failure-behavior) disables the batch. Invalid selections retire only their lane. ### Page-parallel GQA decode

Singleton K0 decode can use page-parallel attention with 1,536–2,560 visible tokens, including the current token. Both prefill policies share decode. Serial eager and serial graph calls can use this path when they select exact attention. Serial graph exact attention requires page-rounded KV capacity of at most 5,120 tokens. [Row dispatch](../src/decoder_forward.cpp#L196)<!-- prefix: "cudaError_t " --> · [Serial graph attention](../src/mxfp8_gqa.cu#L905)<!-- prefix: "cudaError_t " -->

Eager can use this path with one ordinary decode row and zero prefill rows, including independent full-prefix-hit scoring. The width-one graph captures two attention nodes. The live position selects the reduction inside those nodes. A larger KV reservation still permits short replay. [Eager dispatch](../src/text/decoder_graph_packed.cpp#L456)<!-- prefix: "first.narrow" --> · [Bound attention](../src/decoder_forward.cpp#L271)<!-- prefix: "if (batch.si" -->

Each logical 128-token KV page produces an FP32 maximum, denominator, and value numerator per query head. The merge rescales both accumulators against the global maximum, divides, and rounds to BF16. This reduction order can change logits and greedy IDs. The path needs 495,360 bytes of the existing 496,640-byte logits allocation. Outside the window or with insufficient workspace, the exact path uses ordered replay. A nonfinite visible score makes the merged denominator nonfinite. The merge checks the denominator and each channel numerator before writing output. The denominator must be finite and positive. Every numerator in the tile must be finite. If a check fails, the tile recomputes QK scores for that head and replays the tokens in order. The fallback stays in the same graph node. It follows the ordered operator's numerical rules, which can also produce nonfinite output. ### Legacy narrow paged GQA decode

The legacy width-two through width-four graph selects split attention per lane at 8,192 through 16,384 visible tokens. It appends the new KV, runs attention, and gates the outputs on the batch stream. Ordered score and replay nodes handle lanes outside the window. Legacy eager forwards group in-window decode lanes after KV append. Other eager rows at those widths follow the row dispatch. [Bounds](../include/sglang/decoder_cuda.cuh#L95)<!-- prefix: "inline const" --> · [Bound forward](../src/decoder_forward.cpp#L253)<!-- prefix: "void attend_" --> · [Eager forward](../src/decoder_forward.cpp#L304)<!-- prefix: "void attend_" --> · [Bound fallback](../src/mxfp8_gqa.cu#L773)<!-- prefix: "__global__ v" -->

The split assigns 128-token KV pages to 16 partitions. It clamps the last to visible length. Bound width four and eager width four after compaction use a `(16, 12, 4)` grid with 256 threads per block. Blocks share decoded K and V between two adjacent query heads of one KV head. Split widths one through three use one block per query head and partition. [Split launch](../include/sglang/text/mxfp8_gqa_decode.cuh#L214)<!-- prefix: "void launch_" --> · [Paired split](../include/sglang/text/mxfp8_gqa_decode.cuh#L151)<!-- prefix: "__global__ v" -->

Four eight-thread subgroups per warp score four channel groups per pass. Two passes preserve each head's FP32 score tree and ascending group sum. Eight warps accumulate values in the original FMA order. Each head writes separate FP32 partials. The merge rescales the weight sum and value numerator to the global maximum, divides in FP32, and rounds to BF16. Split and ordered attention can produce different logits. Each lane uses 399,360 of its 496,640 logits bytes for 16-byte-aligned partials. In-window lanes skip request-owned score binding. [Paired scores](../include/sglang/text/mxfp8_gqa_decode.cuh#L48)<!-- prefix: "__device__ v" --> · [Merge](../src/mxfp8_gqa.cu#L658)<!-- prefix: "__global__ v" --> · [Scratch alias](../src/decoder_forward.cpp#L248)<!-- prefix: "PagedDecodeB" -->

The merge requires finite numerators and BF16 outputs and a finite positive weight sum. Replay widens the decoded FP32 KV, processes the visible sequence in order, and rounds to BF16. Other heads keep their results. The captured sequence includes both FP64 head replay and ordered lane fallback.
