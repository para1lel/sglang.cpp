## Runtime path

C++ defaults to eight lanes and 32,768 rows per step. Reserve rows for ready decode lanes in admission order. Within the step budget, reserve up to one plus the legal [MTP proposals](mtp.md#runtime-path) per lane. Give the oldest ready prompt the remaining rows up to its end or the next [prefix-cache checkpoint](prefix-cache.md#checkpoint-boundaries). A later prompt can use any remainder. ### TP2 target verification graph

On eligible B200 TP2 systems, one to four lanes can replay one to five contiguous verification rows per lane, including sampled groups and mixed row counts. Complete packed greedy groups can use eight lanes (M40) or sixteen (M80) when packed dispatch qualifies. Both ranks need matching layouts, valid rank-local GQA pages and GDN bindings, vector GQA, and the full 262,144-token split policy. Unsupported row bindings, constrained rows, selected eager lanes, unavailable streams or ineligible MNNVL stay eager. ### Eager TP2 singleton verification

On B200 TP2, one unbound greedy MTP lane with three to five target rows and Tensor Core vocabulary scratch can write packed FP8 directly if both ranks select Tensor Core projections and neither binds an external packed buffer. Sampling, constraints, and requested logits or logprobs bypass this singleton route. Healthy eager MNNVL can also fuse reduction with RMSNorm and quantization. A transport decline keeps ordinary allreduce and local fused preparation. The route preserves BF16 rounding, E4M3 values, and FP32 scales. ## Resident memory admission

HTTP admission uses the general arena capacity after a shared workspace allowance. It checks each request against that limit and current headroom alongside existing reservations. The [GPU arena](serving/request-memory.md) owns free and retired ranges. The [row and lane caps](development.md#native-streaming-server) apply independently. C++ callers can set `DecoderBatchOptions::resident_memory_limit` in bytes to cap admission further. [HTTP setup](../src/runtime/server/single_device_batch_executor.cpp#L92)<!-- prefix: "config.max_n" --> · [C++ option](../include/sglang/decoder_batch.h#L69)<!-- prefix: "std::optiona" --> · [Reservation](../src/runtime/model/qwen_request.cpp#L170)<!-- prefix: "std::size_t " -->

A request needs capacity for its encoded or expanded prompt plus its output budget minus one. The [prefix pool](prefix-cache.md#runtime-path) reserves page-rounded GQA and draft KV separately. The general charge covers page tables, GDN state, workspaces, and any verifier or media storage. A zero-budget request without scoring skips the reservation. [Charge calculation](../src/runtime/model/qwen_request.cpp#L112)<!-- prefix: "std::size_t " --> · [Page reservation](../src/decoder_batch.cpp#L91)<!-- prefix: "target_pages" --> · [Zero budget](../src/decoder_batch.cpp#L276)<!-- prefix: "if (options." -->

Admission can reduce an [implicit chat budget](chat-serving.md#sampling-defaults-and-output-budget) to the fixed limit. Keep explicit budgets. Exceeding the limit returns HTTP 413. If the resident prefix cache reports a retryable shortage, the oldest rejected request gets the next allocation attempt before younger requests while admitted lanes and prefix transfers continue. A terminal capacity shortage or allocation OOM with successful cleanup returns HTTP 503. These capacity errors occur before SSE headers and leave peers running. C++ reports `DecoderCapacityError` with `retryable`. Terminal CUDA status or failed drain disables the batch and fails current jobs. See [readiness](http-server.md#health-and-readiness) and [stream errors](http-server.md#completion-streams). ## Constraints and failure behavior

TP1 K0 executable identity includes width and the ordered positions of the split and paged lanes within the group. Sparse slot selections can rebind after retirement. Prefill runs outside the executable. [Capture and binding](../src/text/decoder_graph.cpp#L137)<!-- prefix: "auto* slot =" --> · [Zero-budget completion](../src/decoder_batch.cpp#L844)<!-- prefix: "result.finis" -->

[Former packed K0 setup and failure rules](https://github.com/para1lel/sglang.cpp/blob/6debe50edccdeda34ff307235ed38e74b6b8f2ee/docs/batch-graphs.md#constraints-and-failure-behavior)

Batch execution owns the winner pin and allocates it on first eligible use. Clean allocation OOM keeps per-lane reads for that batch. Other errors reach batch recovery. Cleanup releases the pin after stream drain and graph teardown. The pin retains ownership until release succeeds. [Allocation](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/src/decoder_resources.cpp#L556)<!-- prefix: "TextLogitCan" --> · [Release](../src/runtime/backend/cuda_resources.cpp#L268)<!-- prefix: "CleanupError" --> · [Retry](../src/runtime/backend/cuda_resources.cpp#L117)<!-- prefix: "static void " -->

Legacy long-score OOM forces eager for that step and later steps needing the failed request's scores. Other requests retain allocations, and recycled slots can replay. Width-local graph scratch OOM or eligible capture, instantiation, or synchronous launch rejection can disable one width. Before eager fallback, end capture, drain the stream, and destroy graph handles. Other widths remain eligible. A target-only execution error outside graph fallback or [prefix recovery](prefix-cache.md#constraints-and-failure-behavior) disables the batch. Invalid selections retire only their lane. ### Page-parallel GQA decode

See [generic SM100 singleton dispatch](singleton-gqa-decode.md#generic-sm100-singleton) for the one direct K0 lane, 1,536–2,560 visible tokens including current, and workspace guard. A width-one graph uses live positions to select inside its attention nodes. The standalone serial route uses [scratch-free attention](singleton-gqa-decode.md#scratch-free-ordered-attention).

Each 128-token page produces an FP32 maximum, mass and value numerator per head. Merge rescales against the global maximum, divides and rounds to BF16. Reduction can change logits or IDs. Page scratch needs 495,360 of the lane's 496,640 logits bytes. Outside the window or without scratch, use ordered replay.

Nonfinite scores invalidate the mass. The merge requires positive finite mass and finite channel numerators. Otherwise the affected head and tile recompute QK and replay in order, within the same graph node. Ordered replay can still produce nonfinite output. ### Legacy narrow paged GQA decode

Legacy width-two through width-four graphs select split attention per lane at 8,192–16,384 visible tokens. The captured sequence appends KV, attends, and gates, with ordered score and replay outside the window. Eager groups eligible decode lanes after append. ## Verification

Build the release server and both probes with `--mxfp8-gqa-check=y` and `--batch-graph-lanes=y` using the [runbook](../tests/batch/README.md). Check bound operators, reuse, recovery, wire parity, and CPU rejection of masks containing a zero-budget slot.

On a reserved B200, compare greedy IDs and full BF16 rows at widths 1–32 wherever the route qualifies. Include sparse slots, rebind, cancellation, zero-budget lanes, score-scratch decline and cleanup after retirement. Check around 2,047 for the direct-to-split route and around 5,120 for the legacy score-backed path. Use [packed-route drift](long-paged-decode.md#packed-route-drift-evidence) and [singleton gates](singleton-gqa-decode.md#verification).

Run [K0 streaming fixtures](development.md#streaming-verification) with default selection and `--eager`. Match IDs, finishes and usage. Trace executables keyed by width and attention shape, masks matching real launches, and zero graph launches on eager steps. Run [wide K0](../tests/batch/README.md#wide-k0-serving) at 16 and 32 lanes, including narrower replay after reuse and slot 31. For positive depth use the [MTP graph checks](mtp.md#verification-graph-checks).

The public TP2 K0 check used two concurrent lanes per greedy and seeded sampled case on two B200s. It matched eager IDs, text, finish reasons, and usage. Dispatch traces showed ordinary decode replay in the default mode and zero replay with `--eager`. Separate C++ checks forced eligible replay through widths 8, 16, and 32 and matched eager IDs. The HTTP check used width two.

A separate packed-projection check matched all 21 selected and alternative scores on 1,664 rows at TP1 widths 1 and 7 and TP2 widths 8, 16 and 32. A mixed-context TP2 width-32 case with one lane replaying through input position 262,142 matched 832 eager tokens and transitions and recorded 25 full two-rank replays from one capture.

The [grouped head checks](../tests/decoder/README.md#grouped-decode-lm-head) require BF16, greedy and seeded parity during capture, replay, mixed steps, and reuse. Require one winner copy per eligible group, or lane copies for pin OOM and diagnostic, sampled, or constrained rows. Cover [rejected pin release](lessons.md#l010--rejected-packed-winner-pin-release).

Use [scheduler admission](../tests/batch/README.md#scheduler-admission) for caps, queueing, reuse, row accounting, and the [admission failure contract](#resident-memory-admission). Verify peer IDs, subsequent completion and readiness after recoverable OOM. On terminal fault, require 500 for new completions, 503 from readiness, and unchanged health limits. Pre-submission rejection and capture failure use eager. Post-submission failure propagates and retains resources until safe. Check reuse under Compute Sanitizer.

Use an FP64 oracle with packed KV for both edges and adjacent lengths of page-parallel and legacy narrow dispatch. Check graph/eager parity, remaps, rebound positions, ordered fallback, masks, scratch guards, and unaffected heads through score overflow and cancellation. ### Capture and replay diagnostics

On a reserved B200, compare default graph selection with `--eager` in the same binary. Keep inputs, active lanes, prefill schedule, and prefix reuse fixed. Time graph capture and isolated replay separately and verify widths in untimed traces. If output IDs diverge, compare full BF16 logits and the winner margin at the first differing step on the common history.
