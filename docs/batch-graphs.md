## Runtime path

Batch execution defaults to eager. Add `--batch-cuda-graphs` at [capacity two or higher](development.md#native-streaming-server) to enable replay for eligible steps. Either prefill policy works with graphs. [Prefix reuse](prefix-cache.md) requires exact prefill. An active MTP lane keeps the step eager, including in mixed-depth C++ selections. [Batch construction](../apps/server/batch_service.cpp#L166)<!-- prefix: "batch = std:" -->

The first eligible step per width runs eager. The next eligible step uses thread-local capture on the batch stream. Widths share batch-owned scratch. Capture keeps the device binding addresses fixed. Each launch uploads tokens, positions, KV page tables, KV and GDN pointers, and GQA score bindings. The graph runs embedding, decoder layers, and per-lane scoring. K0 lanes can mix greedy, sampled, and [constrained requests](text-serving.md#finite-choice-constraints) in one replay. Sampling and constrained selection run on the batch stream after replay. The batch maps winners back to logical slots and synchronizes before publishing or retiring lanes. [Warmup and bindings](../src/decoder_batch.cpp#L389)<!-- prefix: "bool Decoder" --> · [Capture](../src/decoder_forward.cpp#L387)<!-- prefix: "void Decoder" --> · [Selection](../src/decoder_batch.cpp#L427)<!-- prefix: "void Decoder" -->

With `--trace-batches`, each set bit in the 32-bit `graph_slots` mask identifies a replayed logical slot. Slot 31 uses bit 31. `width` counts all selected lanes. `request_bytes` includes request-owned scores and excludes batch scratch, CUDA graph allocations, and prefix cache storage. Active steps report prefill scratch as `workspace_bytes`. After first sampling use, active steps also report `sampling_workspace_bytes`. The batch reuses this sampling allocation across lanes and requests. Active sampling also uses its separate scratch. Each scored constrained row uploads up to 16,384 bytes of IDs. The lane keeps the host ID list live until the step completes. ## Constraints and failure behavior

Each batch caches one executable per eligible packed decode width of two, three, or four. Sparse selections at those widths can replay inside a wider service. They reuse the executable with new bindings after request retirement. Steps with prefill and packed decode outside widths two through four use eager. Wider decode submits one packed forward. Zero-budget lanes can finish on the same step without entering the graph. A full prefix hit scores eagerly and stays out of the replay mask. Eligible decode peers can replay on that step. [Dispatch](../src/decoder_batch.cpp#L489)<!-- prefix: "const bool g" --> · [Full hit](../src/decoder_batch.cpp#L466)<!-- prefix: "if (lane.res" --> · [Zero-budget completion](../src/decoder_batch.cpp#L657)<!-- prefix: "result.finis" -->

Positions 0–5,119 use the logits area in each packed lane's scratch. The first graph binding at a later position allocates scores for that request's page-rounded KV capacity. Each 128-position page needs 12,288 bytes for 24 FP32 scores per position. Capacity is at most 262,144 positions or 24 MiB of scores per lane. W3 reserves 72 pages per lane, or 9,216 positions and 884,736 score bytes. Four W3 lanes add 3,538,944 bytes. The fixed-grid kernels read position and head stride from the current binding. Each request reuses its allocation until retirement after stream completion. [Score allocation](../src/decoder_resources.cpp#L510)<!-- prefix: "ExactGqaWork" --> · [Score launch](../src/mxfp8_gqa.cu#L637)<!-- prefix: "cudaError_t " -->

If the first long-score allocation runs out of memory, the current step runs eager. That request remembers the failure and forces eager on later steps that need its long scores. Allocations already made for other lanes remain owned by those requests and can serve later replays. The executable remains available for other selections and recycled slots. Scratch OOM and recognized capture, instantiation, or synchronous launch rejections can disable one width. That fallback requires ended capture, a drained stream, and destroyed handles. Other widths remain eligible. A target-only execution error that escapes fallback disables the batch and fails current and subsequent requests. An invalid sampled or constrained selection retires only its lane. Cleanup retains resources while completion is uncertain. [Step recovery](../src/decoder_batch.cpp#L687)<!-- prefix: "if (!contain" -->

### Page-parallel GQA decode

Singleton K0 decode can use page-parallel attention with 1,536–2,560 visible tokens, including the current token. Both prefill policies share decode. Serial eager and serial graph calls can use this path when they select exact attention. Serial graph exact attention requires page-rounded KV capacity of at most 5,120 tokens. Device position selects the reduction inside the same two attention graph nodes. [Row dispatch](../src/decoder_forward.cpp#L178)<!-- prefix: "cudaError_t " --> · [Graph dispatch](../src/mxfp8_gqa.cu#L740)<!-- prefix: "cudaError_t " -->

An eager batch step can use this path with one packed decode row, zero prefill rows, and no active MTP lane. An independent full-prefix-hit score can run on that step. Packed graph replay keeps ordered exact GQA. Multi-row forwards, prefill, and MTP verification keep their existing attention paths. [Singleton dispatch](../src/decoder_batch.cpp#L492)<!-- prefix: "work[0].narr" -->

Each logical 128-token KV page produces an FP32 maximum, denominator, and value numerator per query head. The merge rescales both accumulators against the global maximum, divides, and rounds to BF16. This reduction order can change logits and greedy IDs. The path needs 495,360 bytes of the existing 496,640-byte logits allocation. Outside the window or with insufficient workspace, the exact path uses ordered replay. [Position window](../src/mxfp8_gqa.cu#L310)<!-- prefix: "__host__ __d" --> · [Page reduction](../src/mxfp8_gqa.cu#L347)<!-- prefix: "__device__ v" --> · [Workspace](../src/decoder_resources.cpp#L507)<!-- prefix: "return {rein" -->

A nonfinite visible score makes the merged denominator nonfinite. The merge checks the denominator and each channel numerator before writing output. The denominator must be finite and positive. Every numerator in the tile must be finite. If a check fails, the tile recomputes QK scores for that head and replays the tokens in order. The fallback stays in the same graph node. It follows the ordered operator's numerical rules, which can also produce nonfinite output. ## Verification

Follow the [batch graph test runbook](../tests/batch/README.md) to build the release server, `mxfp8-gqa-check`, and `batch-graph-lanes`. Enable `--mxfp8-gqa-check=y` and `--batch-graph-lanes=y` in XMake. The runner checks bound operators, lane reuse, fault recovery, and HTTP parity under both prefill policies. Its CPU regression rejects a mask with the correct population count that includes a zero-budget slot. [Test target](../xmake.lua#L207)<!-- prefix: "option(\"batc" -->

On the reserved B200, compare each width against eager with identical inputs under the same prefill policy. Match greedy IDs and complete BF16 vocabulary rows at equal packed widths. Test singleton transitions separately because changing width can change the GQA reduction order. Cross positions 127–129 and 5,119–5,121. Exercise inline and long strides in one replay. Change slot masks and request bindings at one width. Reject first-use score allocations at different packed lanes. Check retained bytes, eager continuation, and executable reuse after cancellation and slot reuse. Verify repeated bindings reuse existing allocations. Select a zero-budget lane alongside replaying lanes. After retirement, require zero request bytes.

Run the [streaming fixtures](development.md#streaming-verification) and [text checks](text-serving.md#verification) on both HTTP modes. Match IDs, finish reasons, and usage. Correlate every replay mask with its CUDA launch and device activity on the batch stream. Require one reused executable per eligible width and zero graph launches on eager steps. Check that width one and `--eager` reject the batch graph flag. Check that a positive-depth server accepts the flag at widths two through four. Require zero replay launches on steps that include MTP lanes.

Follow the [wide K0 runbook](../tests/batch/README.md#wide-k0-serving). Check full-width eager decode and narrower replay after slot reuse at capacities 16 and 32. Require a replay with logical slot 31 in the mask at capacity 32.

Inject capture failure and pre-submission launch rejection. Require eager continuation at that width and replay at other widths. Inject a post-submission failure to check service error propagation and resource retention until safe cleanup. Check slot reuse under Compute Sanitizer. Retain the default and explicit width-one graph checks and the [MTP checks](mtp.md#verification).

For page-parallel GQA, check both window edges and their neighboring lengths against an FP64 oracle over the same packed KV bytes. Include page remaps, masked future tokens, and insufficient scratch. Check input bytes and scratch guards. Cross both edges with serial eager and with fresh and reused graphs at matching KV capacity. Match the ordered fallback bitwise. Run the [GQA verifier](development.md#p2-gqa-verification).

Exercise finite Q and KV that overflow FP32 scores or page-local value sums. Build the packed KV with the native append operator. When ordered replay and the FP64 oracle agree on a finite result, require the fallback to match in eager and graph modes.

The post-loader smoke used B200 GPU1 and four frozen 8,192-token W3 prompts. Both arms used tensor-core prefill and budgets of 6, 9, 12, and 15. All 42 IDs, finish reasons, and usage matched eager. The IDs matched the frozen output prefixes. CUPTI correlated four replays at width four and two each at widths three and two. The first replay added 798,720 score bytes per lane. Final request bytes were zero. See `artifacts/long-graph-standalone/final-loader/evidence/native/smoke/verified.json`.

## Timing

Compare graph opt-in with batch eager on the same binary and prefill policy. To compare releases, enable batch graphs in both arms and match prefill policy. Freeze requests, arrivals, device, and warmups. Record cold capture separately and verify actual decode widths in a separate trace. Disable observers and trace output for timing. Frozen W3 and W6 begin decode above the inline score capacity.

Before [frozen W1/W2 timing](performance.md#frozen-w1-and-w2-timing), repeat each native route for stable output IDs. If native builds diverge, compare full BF16 logit rows at the first differing step on their common history. Record the winner margin.

An earlier run before parallel MTP used one release binary on B200 GPU3 with driver 590.48.01. Both arms used `--max-active 4 --fp8-prefill exact`. The graph arm added `--batch-cuda-graphs`. MTP, observers, and tracing were off. The process order was eager, graph, graph, eager, with two warmups per process and 14 measured cohorts per arm. Each cohort sent four concurrent requests with 19–29 prompt tokens and returned 32 IDs per request. Maximum prompt plus output was 61 tokens. Timed SSE matched. Median output tokens/s increased from 110.83 to 113.65. Median cohort TPOT fell from 26.41 to 24.18 ms/token. The distributions overlapped, and the two eager process medians were 84.28 and 113.20 tokens/s. The historical record is `artifacts/batch-graph-acceptance/report.md`.
