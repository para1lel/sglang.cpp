Within the step budget, reserve up to one plus the legal [MTP proposals](mtp.md#runtime-path) per lane. Give the oldest ready prompt the remaining rows up to its end or the next [prefix-cache checkpoint](prefix-cache.md#checkpoint-boundaries). A later prompt can use any remainder. ## Resident memory admission

The HTTP batch service derives a fixed request limit from GPU memory free after initialization, reserving up to 2 GiB for shared allocations. Admission checks active reservations and current device memory, including [reclaimable retired blocks](serving/request-memory.md). The [row and lane caps](development.md#native-streaming-server) apply separately. C++ callers can opt in with `DecoderBatchOptions::resident_memory_limit` in bytes. The effective limit is the smaller of that value and the startup limit. [HTTP setup](../src/runtime/server/single_device_batch_executor.cpp#L87)<!-- prefix: "config.max_n" --> · [C++ option](../include/sglang/decoder_batch.h#L70)<!-- prefix: "std::optiona" --> · [Startup limit](../include/sglang/runtime/execution/decoder_batch_state.h#L127)<!-- prefix: "if (options." --> · [Admission check](../src/decoder_batch.cpp#L44)<!-- prefix: "std::size_t " -->

Each positive-budget request reserves page-rounded KV for the encoded or expanded prompt length plus the output budget minus one. The charge includes target KV, GDN state, workspace allowances, and any MTP draft KV, verifier, or media position storage. Admission initializes live storage and prepares shared sampling and constraint buffers when needed. The [daemon](prefix-cache.md#lmcache-daemon) owns cross-request payloads in CPU memory. A zero-budget request without scoring skips the reservation. The batch can reduce a [chat request's implicit output budget](chat-serving.md#sampling-defaults-and-output-budget) to fit the fixed limit. It keeps explicit budgets. HTTP returns 413 above the fixed limit or 503 when current capacity is too low. A CUDA allocation failure during initialization returns 503 if cleanup succeeds. The service retires the failed lane and keeps active peers. These failures return JSON before [SSE opens on admission](http-server.md#completion-streams). C++ callers receive `DecoderCapacityError` with `retryable`. A terminal CUDA status or failed drain disables the batch. The service fails current jobs and reports [worker failure](http-server.md). An open writable stream sends an SSE error and ends without `[DONE]`. ### Page-parallel GQA decode

The generic SM100 policy can use page-parallel attention for one direct K0 batch decode lane with 1,536–2,560 visible tokens, including the current token. It requires enough workspace for page partials. See [singleton dispatch](singleton-gqa-decode.md#generic-sm100-singleton) for score storage and [scratch-free attention](singleton-gqa-decode.md#scratch-free-ordered-attention) for the standalone serial route.

The width-one graph can use the live position to select the reduction inside its attention nodes. [Eager selection](../src/text/decoder_graph.cpp#L92)<!-- prefix: "first.narrow" --> · [Bound attention](../include/sglang/runtime/execution/decoder_forward_layers.h#L713)<!-- prefix: "if (batch.si" -->

Each logical 128-token KV page produces an FP32 maximum, denominator, and value numerator per query head. The merge rescales both accumulators against the global maximum, divides, and rounds to BF16. This reduction order can change logits and greedy IDs. The path needs 495,360 bytes of the existing 496,640-byte logits allocation. Outside the window or with insufficient workspace, the exact path uses ordered replay. A nonfinite visible score makes the merged denominator nonfinite. The merge checks the denominator and each channel numerator before writing output. The denominator must be finite and positive. Every numerator in the tile must be finite. If a check fails, the tile recomputes QK scores for that head and replays the tokens in order. The fallback stays in the same graph node. It follows the ordered operator's numerical rules, which can also produce nonfinite output. ### Legacy narrow paged GQA decode

The legacy width-two through width-four graph selects split attention per lane at 8,192 through 16,384 visible tokens. It appends the new KV, runs attention, and gates the outputs on the batch stream. Ordered score and replay nodes handle lanes outside the window. Legacy eager forwards group in-window decode lanes after KV append. Other eager rows at those widths follow the row dispatch. [Bounds](../include/sglang/decoder_cuda.cuh#L289)<!-- prefix: "inline const" --> · [Bound forward](../include/sglang/runtime/execution/decoder_forward_layers.h#L694)<!-- prefix: "inline void " --> · [Eager forward](../include/sglang/runtime/execution/decoder_forward_layers.h#L781)<!-- prefix: "void attend_" --> · [Bound fallback](../src/mxfp8_gqa.cu#L703)<!-- prefix: "__global__ v" -->

The split assigns 128-token KV pages to 16 partitions. It clamps the last to visible length. Bound width four and eager width four after compaction use a `(16, 12, 4)` grid with 256 threads per block. Blocks share decoded K and V between two adjacent query heads of one KV head. Split widths one through three use one block per query head and partition. [Split launch](../include/sglang/text/mxfp8_gqa_decode.cuh#L227)<!-- prefix: "void launch_" --> · [Paired split](../include/sglang/text/mxfp8_gqa_decode.cuh#L151)<!-- prefix: "__global__ v" -->

Four eight-thread subgroups per warp score four channel groups per pass. Two passes preserve each head's FP32 score tree and ascending group sum. Eight warps accumulate values in the original FMA order. Each head writes separate FP32 partials. The merge rescales the weight sum and value numerator to the global maximum, divides in FP32, and rounds to BF16. Split and ordered attention can produce different logits. Each lane uses 399,360 of its 496,640 logits bytes for 16-byte-aligned partials. In-window lanes skip request-owned score binding. [Paired scores](../include/sglang/text/mxfp8_gqa_decode.cuh#L48)<!-- prefix: "__device__ v" --> · [Merge](../src/mxfp8_gqa.cu#L584)<!-- prefix: "__global__ v" --> · [Scratch alias](../include/sglang/text/gqa_verify_batch.h#L64)<!-- prefix: "inline Paged" -->

The merge requires finite numerators and BF16 outputs and a finite positive weight sum. Replay widens the decoded FP32 KV, processes the visible sequence in order, and rounds to BF16. Other heads keep their results. The captured sequence includes both FP64 head replay and ordered lane fallback. ## Timing

Compare default graph selection with `--eager` on one binary. Keep prefill policy fixed and prefix reuse off. Match graph and prefill policies across releases. Freeze requests, arrivals, device, and warmups. Record cold capture separately. Verify widths in a separate trace. Disable observers and tracing for timing. Measure whole-request latency separately from replay. The historical W3 and W6 fixtures began decode above inline score capacity.

Before timing, repeat each native route for stable output IDs. If native builds diverge, compare full BF16 logit rows at the first differing step on their common history. Record the winner margin. Use the [strict concurrent policy](performance.md#native-concurrent-workloads) for HTTP serving.
