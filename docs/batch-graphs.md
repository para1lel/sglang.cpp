## Resident memory admission

The HTTP batch service derives a fixed request limit from GPU memory free after initialization, reserving up to 2 GiB for shared allocations. Admission checks active reservations and current device memory, including [reclaimable retired blocks](serving/request-memory.md). The [row and lane caps](development.md#native-streaming-server) apply separately. C++ callers can opt in with `DecoderBatchOptions::resident_memory_limit` in bytes. The effective limit is the smaller of that value and the startup limit. Each positive-budget request reserves page-rounded KV for the encoded or expanded prompt length plus the output budget minus one. The charge includes target KV, GDN state, workspace allowances, and any MTP draft KV, verifier, or media position storage. Admission initializes live storage and prepares shared sampling and constraint buffers when needed. The [daemon](prefix-cache.md#lmcache-daemon) owns cross-request payloads in CPU memory. A zero-budget request without scoring skips the reservation.
