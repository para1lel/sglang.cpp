## Runtime path

### Exact SIMT projections

For eligible wide inputs, the exact projection selects the eight-row launcher at 64 or more prompt rows and more than 1,024 output channels. With 5,120, 6,144, or 17,408 input channels and an output width at most 65,535, the launcher can assign four prompt rows and four adjacent output channels to each warp if the output width is divisible by four. For 64–128 prompt rows and an output width divisible by eight, it assigns eight adjacent channels per warp and reuses each decoded FP8 operand across the corresponding rows or channels. Every output retains its two ordered FP32 dot-product chains, scaling, warp reduction, and BF16 rounding. Other eligible shapes use the existing row tiles. ### Tensor-core projections

On B200, the native runtime selects packed Tensor Core projections for eligible prefill and target decode. Dispatch depends on the operation, device, buffers, and row shape. Media embeddings and scoring use the same target layers. [Prefix restore](prefix-cache.md#checkpoint-compatibility-and-resume) supplies lane state before the remaining rows run.

Short target projections use the SM100 Swap-AB FP8 operator for one to five text rows. It reads the FP32 activation scales and BF16 checkpoint weight scales and writes BF16 results to the destination rows. Multi-row calls use a row-major E4M3 activation buffer for an eight-column TMA tile. Fused quantizers write five verification rows or [eligible TP2 singleton rows](batch-graphs.md#eager-tp2-singleton-verification) directly into that buffer with per-row FP32 scales. Other multi-row calls can pack the activation values before launching the projection. GDN QKV and Z, GQA QKV, and MLP gate and up share one packed activation per group and write to separate BF16 destinations. Scalar text decode uses the same split planner as verification. This grouping changes where the FP32 partials are added, so comparisons between K0 and K4 use the same projection policy and implementation. Unsupported projections and devices use exact target dispatch, including the staged five-row kernel where eligible. A per-lane guard keeps multimodal decode on its mRoPE-aware path, including in a mixed batch.

For eligible GDN verification, one launch projects the BF16 b and a gates for two to five rows. A CTA loads one gate weight row into shared memory and each warp computes it for one verification row. The kernel keeps the two ordered FP32 accumulation chains, warp reduction, and BF16 rounding. Scalar decode, exact verification, and ineligible inputs use the existing gate projections. ### Multi-lane target verification

Four-lane packets batch activation quantization at six to twenty rows. With a packed activation buffer, [wide K4 verification](mtp.md#target-round) batches 40, 80, or 160 rows per launch. This covers RMSNorm, attention output, and SwiGLU quantization. [Compact GDN](gdn-prefill.md#grouped-target-verification) writes FP8 during finish, bypassing separate output quantization. Rows keep BF16 rounding, E4M3 values, FP32 scales, and output slots. ### Large prefill tiles

Separate tensor-core K0 projections require at least three rows, input widths divisible by 128, and contiguous, 16-byte-aligned E4M3 payloads. The output can end in a partial tile. At 129–1,023 rows, projections with at least 8,192 output channels or 6,144 input channels first try a paired-TMA 128×128 tile. The launch places the row tiles for each column tile next to one another to improve weight cache reuse. ### Attention output quantization

For ordinary tensor-core text prefill, GDN combines gated RMSNorm with FP8 quantization. Each warp rounds one head to BF16 in registers before quantization. The output projection consumes the E4M3 values and FP32 scales directly. In grouped prefill, each grant writes its own rows in the shared activation buffer. The separate GQA gate and the BF16 GDN prefill path pass 6,144 channels per row to `text_quantize_fp8_rows`. [Fused finish](../src/text_attention_gdn.cu#L489)<!-- prefix: "__global__ v" --> · [GDN call](../src/decoder_prefill.cpp#L635)<!-- prefix: "chunk.gdn_at" --> · [GQA call](../src/decoder_prefill.cpp#L630)<!-- prefix: "chunk.projec" -->

On B200, the native GQA gate and quantizer can fuse for 4,096-row [strict MTP](native-prefill-workspace.md#projection-pairs-for-mtp), [uniform partial-grant](native-prefill-workspace.md#partial-grant-projection-groups), and [same-request causal groups](flash-prefill.md#same-request-causal-gqa). The kernel rounds gated values to BF16 before it writes E4M3 values and FP32 scales. If fusion declines, strict and causal groups gate the full buffer, and partial groups gate each grant. Both then use ordinary quantization. TP2 requires fusion on both ranks to use those outputs. CUDA errors propagate. ### Fused activation quantization

Packed decode and tensor-core prefill share the fused RMSNorm launcher. For ordinary small tiles, the eight-lane quantizer requires 2–32 launch rows, width 5,120, and a residual buffer. In packed decode, the bucket width sets the launch row count. Branch, residual, and gain buffers require 16-byte alignment. The E4M3 output requires 8-byte alignment. Eligible prefill tiles also use this path. Other valid calls use the existing fused kernel or separate RMSNorm and quantization according to width and input alignment. Capture or misalignment uses ordinary normalization and stores BF16. CUDA errors propagate. ## Constraints and failure behavior

The `sm_100a` TMA, TMEM, and `tcgen05` path requires capability 10.0, a matching image, sufficient opt-in shared memory, and tensor maps. Output slices must be disjoint from inputs and each other. Clean separate and packed declines try the ordinary shape-selected tile and 128×128 tile, respectively. If packing declines, the decoder projects slices separately. Ineligible Tensor Core calls use SIMT. CUDA errors propagate. Attention output quantization requires a valid FP32 scale buffer with ordinary float alignment. Other valid shapes or alignments use the scalar kernel, which supports partial groups. Fused SwiGLU shares the warp kernel and retains its own dispatch and BF16 rounding. On B200, compare complete BF16 slices against the 128×128 control for both QKV checkpoint shapes. Include a ragged tile. Include a slice width with a 128-column remainder modulo 256. Measure projection latency separately with resident buffers.

For gate/up, use a 128×128 control with the same tile groups. Compare BF16 slices, FP8 activations and scales, and down outputs. Check row counts adjacent to 1,024. Time isolated projection with resident checkpoint weights.

For down, build the paired-mode `tests/text/fp8_prefill_tiling_check.cpp` from the acceptance change against both release libraries. Link with `-Wl,--wrap=cudaLaunchKernel -Wl,--wrap=cudaFuncGetAttributes`. Run both on a reserved B200 with the same checkpoint and a fresh reference directory.

```bash
"$control_check" "$checkpoint" wide-base "$reference_dir"
"$candidate_check" "$checkpoint" paired "$reference_dir"
```

Measure isolated graph replay with checkpoint weights and prepared SwiGLU activations. Keep operator latency and archive-based call exposure in the run record.

For the shared collective, fix grants and readers. Cover grouped GQA and GDN output and MLP down for four full tiles and 4,096 unequal partial-group rows, plus ordinary 1,024-row down. Use identical tiles and GQA readers in both arms. Test strict groups of four 1,024-row tiles and partial groups of eight 512-row or sixteen 256-row grants. Exercise staged and per-lane readers for strict groups. Exercise staged, raw grouped, and per-lane readers for partial groups.
