## Runtime path

Before GDN input preparation, eligible tensor-core prefill tiles project B and A together from the normalized BF16 input. Each warp shares an input load across both gates and reuses each gate's weights across four token rows. Packed FP32 FMA preserves the separate projections' two accumulation chains per lane. The kernel adds those chains, reduces across the warp in the same order, and rounds each output to BF16. [Fused projection](../src/text_decode_bandwidth.cu#L99)<!-- prefix: "__global__ v" --> · [Separate projection order](../src/text_ops.cu#L92)<!-- prefix: "for (std::si" -->

The default `exact` policy uses the original token-ordered GDN recurrence. Positive-depth MTP prefill also uses that path. With `tensor-core`, GDN first prepares convolution, normalized Q and K, and gates. The SM100 chunked route then prepares causal matrices in groups of 32 token rows. It uses BF16 Tensor Core products with FP32 accumulation to solve for corrections and advance the carry. The recurrence uses BF16 operands for the incoming carry projection, including between groups. Persistent carry remains FP32. The finish updates BF16 convolution history and supplies the [attention output projection](fp8-prefill-projections.md#attention-output-quantization). [Matrix preparation](../include/sglang/text/gdn_chunk.cuh#L158)<!-- prefix: "__global__ v" --> · [Chunked recurrence](../include/sglang/text/gdn_warp_mma.cuh#L301)<!-- prefix: "__global__ v" -->

Grouped input preparation assigns four consecutive rows to each 128-thread convolution block. Each channel reuses the four filter weights and a rolling input window. Each output uses its current sample and the preceding three raw samples. Rows before the tile read the incoming BF16 convolution history. The kernel rounds SiLU to BF16 before Q and K normalization and preserves each row's reduction order. A separate block in the same launch prepares the gates for each four-row group. [Grouped preparation](../src/text_attention_gdn.cu#L194)<!-- prefix: "__global__ v" --> · [History read](../src/text_attention_gdn.cu#L46)<!-- prefix: "__device__ _" -->

Per-grant matrix preparation uses one 128-thread block per value head and row group. Recurrence uses a `48 × 2` grid with 256 threads per block. Eight warps share the staging work in each block. Each warp processes eight value channels, so the two blocks cover all 128 channels per head. [Matrix launch](../include/sglang/text/gdn_chunk.cuh#L219)<!-- prefix: "const auto s" --> · [Recurrence launch](../include/sglang/text/gdn_chunk.cuh#L225)<!-- prefix: "return cudaL" --> · [Channel assignment](../include/sglang/text/gdn_warp_mma.cuh#L213)<!-- prefix: "const int fe" -->

On SM100, an existing [layerwise prefill group](native-prefill-workspace.md#multi-request-text-prefill) of two or three eligible grants can share the preparation, matrix, recurrence, and finish launches. The grid Z coordinate selects a grant with its own state and scratch spans. Each block uses the selected grant's row count, including when aligned grant lengths differ. The first GDN layer uses the per-grant path for the whole group when any grant starts at position zero. [Grouped submission](../src/text_attention_gdn.cu#L766)<!-- prefix: "std::optiona" -->

Grouped matrix preparation uses one 384-thread block per Q and K head and row group. The three associated value heads share Q and K staging and the FP32 dot products. Each value head applies its own gates and solves its own triangular system with the existing BF16 matrix layout. [Grouped matrix launch](../include/sglang/text/gdn_chunk.cuh#L234)<!-- prefix: "const auto s" -->

The ordered tensor-core fallback uses the paired kernel for at least 32 rows with 16-byte-aligned recurrence workspace. Otherwise it uses the original recurrence. The paired kernel shares prepared Q, K, and gates between adjacent value channels. SM100 uses packed FP32 arithmetic and preserves each channel's token, update, and warp reduction order. Other compiled architectures use scalar arithmetic in this paired kernel. [Paired kernel](../src/text_attention_gdn.cu#L289)<!-- prefix: "__global__ v" --> · [Paired guard](../src/text_attention_gdn.cu#L670)<!-- prefix: "const bool p" -->

## Constraints and failure behavior

The fused B/A projection requires `tensor_core_fp8` and two BF16 weight matrices of 48 rows by 5,120 columns each. The input row count must be a multiple of four between 16 and 65,535 inclusive. Both weights, the input, and both outputs must have nonnull pointers. Both weight bases and the input base require 16-byte alignment. If a guard fails, the decoder uses the existing separate projections in B then A order. A fused launch error propagates to the caller. [Policy and shapes](../src/decoder_prefill.cpp#L283)<!-- prefix: "if (tensor_c" --> · [Launch guards](../src/text_decode_bandwidth.cu#L305)<!-- prefix: "if (rows \u003c 1" --> · [Fallback](../src/decoder_prefill.cpp#L294)<!-- prefix: "project(laye" -->

The first GDN layer uses ordered recurrence for a tile that starts at prompt position zero. Later GDN layers in that tile and all GDN layers in subsequent tiles may use chunked recurrence. A tile that resumes a saved prefix uses the absolute restored position. An earlier recurrence experiment on W2 found that reordering only the first GDN call could change later model scores. The guard preserves that call's update order.

Tensor-core prefill uses grouped input preparation at 128 rows and above when the row count is divisible by four. Other counts use one row per preparation block. Preparation selects its route independently of matrix scratch and the recurrence route. The position-zero first GDN layer can therefore use grouped preparation with ordered recurrence. Groups write disjoint workspace rows and gates. The finish saves three raw BF16 samples per channel after preparation and recurrence on the same stream. State ownership and workspace sizes stay the same. [Shape guard](../src/text_attention_gdn.cu#L660)<!-- prefix: "const bool g" --> · [History write](../src/text_attention_gdn.cu#L484)<!-- prefix: "final_histor" -->

Chunked recurrence requires SM100, at least 128 rows per call, and sufficient 32-byte-aligned matrix scratch. The decoder borrows the MLP gate buffer until the recurrence consumes the matrices on the same stream. The later gate projection can then write the buffer. Chunked recurrence leaves request-state and pool sizes unchanged. Calls below 128 rows or with unavailable, short, or unaligned scratch use the ordered fallback. A single-row tail uses the existing single-row path. CUDA discovery, configuration, and launch errors propagate. [Scratch guard](../include/sglang/text/gdn_chunk.cuh#L186)<!-- prefix: "inline bool " --> · [CUDA configuration](../include/sglang/text/gdn_chunk.cuh#L191)<!-- prefix: "inline cudaE" -->

Each 32-row group needs one 4,480-byte matrix record per value head. At 1,024 rows, 32 groups across 48 heads use 6,881,280 bytes (6.5625 MiB) of the borrowed buffer. The two causal matrices have a 32-element BF16 row pitch in global scratch and a 40-element pitch in shared memory. The shared pitch shifts successive rows across bank groups. Each recurrence block uses 45,824 bytes of dynamic shared memory for its two staging buffers. [Global layout](../include/sglang/text/gdn_chunk.cuh#L23)<!-- prefix: "struct align" --> · [Scratch size](../include/sglang/text/gdn_chunk.cuh#L182)<!-- prefix: "inline std::" --> · [Shared layout](../include/sglang/text/gdn_warp_mma.cuh#L112)<!-- prefix: "struct Stage" --> · [Dynamic size](../include/sglang/text/gdn_warp_mma.cuh#L155)<!-- prefix: "constexpr in" -->

The explicit `tensor-core` policy permits reordered recurrence. BF16 output, FP32 carry, logits, and generated IDs can differ from ordered execution. Chunked GDN and [flash GQA](flash-prefill.md#runtime-path) qualify independently within the same prefill tile.

## Verification

On a reserved B200, build the segmented probe with `SGLANG_TEST_GDN_TILED` and wrap `cudaLaunchKernel` at link time. Run `segmented paired CAPTURE` on both the packed candidate and the scalar paired control. The probe starts with nonzero history and recurrent state and carries them through eight segments. It checks at least the 31-, 32-, and 33-row boundary and a two-byte workspace offset.

Require bitwise equality of BF16 output, FP32 carry, and BF16 history across the CUDA paths. Require exact history and apply the probe tolerances for output and carry against the scalar FP64 CPU oracle. Run `short paired CAPTURE` under memcheck, racecheck, initcheck, and synccheck. Require zero errors and hazards.

Follow the [CUDA check instructions](../tests/decoder/README.md#gdn-prefill) on a reserved B200. Use `gdn-check chunked` for the 127-, 128-, and 129-row dispatches and the 193-row tail. For eligible calls, check the preparation and recurrence launch dimensions given in [Runtime path](#runtime-path). Check scratch alignment, one-byte shortfall, guards, and causality across a group boundary. Compare against the independent FP64 oracle with the probe's output and carry error limits. Require exact BF16 convolution history and bitwise equality for ordered fallbacks.

Use `gdn-routes` to check the first tile and a tile restored from a prefix while another lane decodes. Expect one ordered and 47 chunked calls on the first eligible tile, and 48 chunked calls on the restored tile. Decode-only steps use no chunked GDN. Check lane retirement and reuse. Compare exact-policy IDs and scores across builds.

Run the checkpoint probe with 2,048 prompt IDs and eight fixed teacher IDs. Leave `SGLANG_SERIAL_PREFILL_ROWS` unset. Require two 1,024-row prefill tiles. For ordered changes, compare carries and histories across all 48 GDN layers after each tile and the decode sequence. Compare full BF16 logits and winners along the fixed history.

For grouped preparation changes, compare output, carry, and history bitwise across builds. Check the 127-, 128-, and 129-row boundary and perturb a later row within a four-row group. Require earlier outputs to match. Measure each stage and the preparation-to-finish interval on the same checkpoint tiles in both run orders. Record any serving estimate with its archived launch count and label it as an estimate.

For reordered changes, compare logits and labeled-token negative log likelihood on identical prompt and teacher histories. Record greedy divergence separately. Trace the position-zero first-layer guard, eligible layers, short tails, exact, and positive-depth MTP. Use the [frozen serving protocols](performance.md) with matched tile schedules, graph settings, and warmups. To isolate GDN when flash is active, hold flash dispatch fixed across both arms.

For recurrence layout changes, compare BF16 output and FP32 carry bitwise against the prior chunked kernel, starting from nonzero carry. Time the isolated recurrence separately from serving. In the matched-prefill W6 diagnostic, recurrence time fell and all generated IDs, usage, and finish reasons matched. Flash GQA dominated GPU kernel time, and the one cohort showed a small wall-time change. The diagnostic used extended transport timeouts and supplies no score under the [frozen W6 protocol](../benchmarks/concurrent/README.md#conditions-and-gates).

The packed ordered implementation preserved BF16 logits in the checkpoint comparison and reduced the measured 1,024-row operator time. The chunked comparison with flash active reduced measured W1 and W2 TTFT. Keep warmup samples separate from measured TTFT. Report their variability and peak device memory with the serving results.

Mean loss changes on the natural documents were small, and their 95% block bootstrap intervals spanned zero. With fixed teacher histories, the authored W2 fixture had a mean NLL increase of 0.331159 nats/token and a mean absolute change of 2.532213 nats/token. Its 95% block bootstrap interval for the mean was [−0.737524, +1.292365] nats/token. Top-1 predictions changed at 44 of 128 teacher positions. In a separate free-running greedy comparison, the two W2 streams first differed on the sixth generated token.
