# Native HTTP transport

The loopback server uses one HTTP reader and one batch scheduler at every capacity. See the [launch procedure](../README.md#serve-token-ids-over-http) for server options. [Startup](../apps/sglang-server.cpp#L170)<!-- prefix: "serve_connec" -->

Send empty GET requests to `/health` and `/ready`. `/health` returns HTTP 200 with the limits. `/ready` returns HTTP 200 with `{"ready":true}`. After permanent decoder worker failure, it returns HTTP 503 with `{"ready":false,"reason":"worker_failed"}`. Both routes bypass the completion queue. New completions return HTTP 500 after permanent decoder worker failure. The [cache controls](prefix-cache.md#native-http-controls) require prefix reuse. ## HTTP admission and shutdown

Let `A` be `--max-active`. The nonblocking loopback listener uses a TCP backlog setting of 16. The reader polls all retained sockets and advances each request incrementally. It retains up to `A + 1` incomplete requests. The reader services ready and expired reads before accepting a waiting connection. The five-second read deadline starts at acceptance and covers receipt of the HTTP headers and body. The header and body limits are 8 KiB and 2 MiB, respectively. Clients can use `shutdown(SHUT_WR)` after a complete request. [Listener](../apps/server/http.cpp#L283)<!-- prefix: "Socket liste" --> · [Reader](../apps/server/http.cpp#L350)<!-- prefix: "void read_co" --> · [Read limits](../apps/server/http.cpp#L27)<!-- prefix: "constexpr st" -->

When a connection is waiting and the reader is full, the reader looks for the oldest eligible incomplete socket. A socket is eligible if it has no readable data and has been idle for at least 250 milliseconds since acceptance or its last successful read. The reader defers acceptance if no socket is eligible. It closes the eligible socket after accepting the new one. During replacement, the socket count can briefly exceed the reader limit by one. [Socket replacement](../apps/server/http.cpp#L325)<!-- prefix: "static void " -->

After HTTP parsing, `POST /v1/completions` and `POST /v1/chat/completions` enter a FIFO in admission order. Up to `A` requests can wait, and up to `A` workers can claim requests. Completion workers parse the request JSON after they claim a request. The queue removes disconnected waiters before checking capacity. It returns a JSON HTTP 503 response when `A` requests are still waiting, even if some workers are idle. A claimed completion keeps its slot until its response socket closes. A TCP reset or failed write cancels active decoder work. The batch retires that work before slot reuse, and ready peers can advance while a writer blocks. [Admission](../apps/server/prefix_controls.cpp#L252)<!-- prefix: "void Connect" --> · [Worker](../apps/server/prefix_controls.cpp#L303)<!-- prefix: "void Connect" --> · [Cancellation](../apps/server/batch_service.cpp#L430)<!-- prefix: "void BatchSe" -->

On shutdown, the reader closes incomplete sockets. The queue discards pending work and joins the completion workers before the batch service is destroyed. The server then propagates the first error that escapes the transport reader or workers. [Shutdown](../apps/server/prefix_controls.cpp#L366)<!-- prefix: "queue.stop()" -->

## Verification

Run the [CPU reader and queue checks](../tests/prefix/README.md#cpu-reader-queue) with prefix reuse off and on. Check the reader limit and absolute deadline for partial headers and bodies. Check that large buffered requests reach the completion queue. Check overload, FIFO replacement after cancellation, and worker shutdown. Require health and readiness responses while partial reads or completions occupy their respective slots. With prefix reuse on, send a reset while a completion holds its slot. Require HTTP 409. Require health and readiness responses while reset acknowledgement is pending.

Run the [streaming verification](development.md#streaming-verification) on a reserved B200 for native decoder behavior.
