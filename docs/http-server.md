# Native HTTP transport

The loopback server uses one HTTP reader and one batch scheduler at every capacity. See the [launch procedure](../README.md#serve-token-ids-over-http) for server options. [Startup](../apps/sglang-server.cpp#L218)<!-- prefix: "serve_connec" -->

Send empty GET requests to `/health` and `/ready`. `/health` returns HTTP 200 with the limits. `/ready` returns HTTP 200 with `{"ready":true}`. After permanent decoder worker failure, it returns HTTP 503 with `{"ready":false,"reason":"worker_failed"}`. Both routes bypass the completion queue. New completions return HTTP 500 after permanent decoder worker failure. The [cache controls](prefix-cache.md#native-http-controls) require prefix reuse. ## Model discovery

Send `GET /v1/models` with an empty body. The route bypasses the completion queue and works with prefix reuse off or on. The server returns HTTP 200 and a JSON object with `object: "list"` and one card in `data`. [Control route](../apps/server/prefix_controls.cpp#L239)<!-- prefix: "void Connect" --> · [Model card writer](../apps/server/prefix_controls.cpp#L229)<!-- prefix: "void write_m" -->

The card uses `Qwen3.8-27B-FP8` for `id` and `root`. Use this ID for native chat and text completions. The card sets `object` to `model`, `owned_by` to `sglang`, and `parent` to `null`. The `created` field gives the response creation time in integer Unix seconds. The `max_model_len` field gives the 262,144-token context shared by prompt and output. Available GPU memory can reduce the admitted capacity. The `benchmark` alias belongs to the [token-ID API](../benchmarks/streaming/README.md#wire-contract).

After successful HTTP parsing, a POST or a GET with a body to `/v1/models` returns HTTP 404.

Use [native model information](native-model-info.md) for the checkpoint paths, model capabilities, and configured chat parsers.

## HTTP admission and shutdown

Let `A` be `--max-active`. The nonblocking loopback listener uses a TCP backlog setting of 16. The reader polls all retained sockets and advances each request incrementally. It retains up to `A + 1` incomplete requests. The reader services ready and expired reads before accepting a waiting connection. The five-second read deadline starts at acceptance and covers receipt of the HTTP headers and body. The header and body limits are 8 KiB and 2 MiB, respectively. Clients can use `shutdown(SHUT_WR)` after a complete request. [Listener](../apps/server/http.cpp#L309)<!-- prefix: "Socket liste" --> · [Reader](../apps/server/http.cpp#L376)<!-- prefix: "void read_co" --> · [Read limits](../apps/server/http.cpp#L29)<!-- prefix: "constexpr st" -->

When a connection is waiting and the reader is full, the reader looks for the oldest eligible incomplete socket. A socket is eligible if it has no readable data and has been idle for at least 250 milliseconds since acceptance or its last successful read. The reader defers acceptance if no socket is eligible. It closes the eligible socket after accepting the new one. During replacement, the socket count can briefly exceed the reader limit by one. [Socket replacement](../apps/server/http.cpp#L351)<!-- prefix: "static void " -->

After HTTP parsing, completions, [`POST /generate`](native-generate.md), and the [tokenization routes](native-tokenization.md) enter one FIFO. Up to `A` requests can wait, and up to `A` workers can claim requests. The queue removes disconnected waiters before checking capacity. It returns a JSON HTTP 503 response when `A` requests are still waiting, even if some workers are idle. The reader checks the shape of `/generate` and reserves its IDs after this capacity check. Workers validate the prompts and options. A normally claimed request holds its HTTP worker slot until its response socket closes. [Queue admission](../apps/server/prefix_controls.cpp#L320)<!-- prefix: "void Connect" --> · [Worker](../apps/server/prefix_controls.cpp#L385)<!-- prefix: "void Connect" -->

A [text completion batch](text-serving.md#send-a-request) or [native generation batch](native-generate.md#runtime-path) counts as one request for HTTP admission. Its items share decoder capacity with other completions. Tokenization uses an HTTP worker and runs on the CPU, including after permanent decoder worker failure. For generation, a TCP reset or failed write cancels unfinished items. The batch retires active lanes before slot reuse, and ready peers can advance while a writer blocks. [Cancellation](../apps/server/batch_service.cpp#L518)<!-- prefix: "void BatchSe" -->

[`POST /abort_request`](native-abort.md) runs on the reader after HTTP parsing. It bypasses the completion queue and works when every generation slot is occupied. It shares the same incomplete-request capacity, replacement policy, and deadlines as other controls. A separate CPU worker can remove a fully aborted generation request from the FIFO and send its result without a generation slot. Partially aborted batches stay in the FIFO. [Control route](../apps/server/prefix_controls.cpp#L239)<!-- prefix: "void Connect" --> · [Abort worker](../apps/server/prefix_controls.cpp#L412)<!-- prefix: "void Connect" -->

On shutdown, the reader closes incomplete sockets. The queue discards pending work and joins the HTTP workers before the batch service is destroyed. The server then propagates the first error that escapes the transport reader or workers. [Shutdown](../apps/server/prefix_controls.cpp#L496)<!-- prefix: "queue.stop()" -->

## Completion streams

For benchmark, text, chat, and `/generate` streams, the completion worker opens chunked HTTP 200 SSE after successful decoder admission. The scheduler signals admission after `admit` or `admit_multimodal` succeeds. The worker calls `on_admitted` before delivering a pending token or successful terminal result. A text completion batch or `/generate` batch opens one stream when at least one item has been admitted and the worker has observed no item error. Headers can arrive while prefill is still running. Nonstreaming text, chat, and `/generate` return JSON when generation finishes. [Decoder admission](../apps/server/batch_service.cpp#L322)<!-- prefix: "job-\u003eadmitte" --> · [Single-request callback order](../apps/server/batch_service.cpp#L532)<!-- prefix: "const bool a" --> · [Batch callback order](../apps/server/batch_service.cpp#L694)<!-- prefix: "bool BatchSe" --> · [SSE headers](../apps/server/http.cpp#L488)<!-- prefix: "bool EventSt" -->

A fully aborted `/generate` request can open SSE to deliver its abort results without decoder admission. A stream that completes with abort results sends one `[DONE]`. [Waiting response](../apps/server/native_generate.cpp#L223)<!-- prefix: "void complet" -->

Before SSE opens, failures use JSON HTTP responses. Invalid completion requests return 400, queue overload returns 503, and [decoder capacity failures](batch-graphs.md#resident-memory-admission) return 413 or 503. Unexpected completion failures before headers return 500. Once SSE opens, the HTTP status stays 200. If generation throws, the worker attempts an SSE error event and ends the stream without `[DONE]`, even if it has sent zero tokens. [JSON error mapping](../apps/server/prefix_controls.cpp#L36)<!-- prefix: "void handle_" --> · [Benchmark error event](../apps/server/completions.cpp#L155)<!-- prefix: "} catch (con" --> · [Text and chat error event](../apps/server/text_completion.cpp#L58)<!-- prefix: "void complet" -->

After admission, the worker polls the SSE writer while waiting for decoder results. For a single request, it skips the poll when an error or finish is pending. For a text completion batch or `/generate` batch, it polls once per consumption loop before checking for failures and ready results. At 15 seconds of wire silence, the next eligible poll sends `:\n\n`. The writer uses a monotonic clock and restarts the interval after a successful header, data, or comment write. Any item event restarts the shared batch clock. Buffered tokens that produce no SSE bytes leave the timer unchanged. A failed write cancels the request. Clients skip comments and measure [TTFT](performance.md#measurement) at the first actual output token. Headers, comments, role events, and usage carry no output tokens. ## Decode scheduling

A job keeps a decoder step in its FIFO mailbox until its completion worker accepts delivery. The entry remains charged while the callback runs outside the scheduler mutex. In ordinary scheduling, a lane with pending output waits for this acknowledgement. A cancelled lane wakes the decoder worker for retirement. [Mailbox](../apps/server/batch_service.cpp#L21)<!-- prefix: "struct Outpu" --> · [Single-request acknowledgement](../apps/server/batch_service.cpp#L558)<!-- prefix: "job.pending." --> · [Batch acknowledgement](../apps/server/batch_service.cpp#L683)<!-- prefix: "job.pending." -->

When any lane is ready, the decoder worker gives other lanes up to 1 millisecond to get ready. With `--max-active 32`, `--batch-cuda-graphs`, and MTP disabled, this grace can end as soon as at least 25 lanes are ready. All 32 slots must hold uncancelled jobs that have published their first token. First-token publication counts with prefix reuse off or on. At 24 ready lanes, the normal wait conditions still apply. [Grace interval](../apps/server/batch_service.cpp#L77)<!-- prefix: "constexpr au" --> · [Early dispatch conditions](../apps/server/batch_service.cpp#L253)<!-- prefix: "bool BatchSe" --> · [Wait](../apps/server/batch_service.cpp#L270)<!-- prefix: "std::optiona" --> · [Publication](../apps/server/batch_service.cpp#L343)<!-- prefix: "void BatchSe" -->

The worker rechecks each selected job before dispatch. It can select every ready lane in the snapshot. Lanes that acknowledge later can run in a subsequent step. If 25 to 32 selected lanes all qualify for [packed decode](batch-graphs.md#runtime-path), the decoder uses the same 32-row bucket. A step with 25 ready lanes can therefore start sooner, with a separate step for the other seven if they acknowledge later. [Readiness check](../apps/server/batch_service.cpp#L294)<!-- prefix: "bool BatchSe" --> · [Bucket selection](../src/text/decoder_graph_packed.cpp#L221)<!-- prefix: "bool PackedD" -->

### Bounded decode output

The benchmark ID stream on `/v1/completions` and the single-prompt `/generate` stream opt in through `DecoderCallbacks::buffer_decode_output`. The callback flag defaults to false. OpenAI text completions in all prompt forms, chat completions, batch `/generate` including one-item lists, and nonstreaming generation use ordinary readiness. [Callback flag](../include/sglang/decoder.h#L84)<!-- prefix: "bool buffer_" --> · [Benchmark stream](../apps/server/completions.cpp#L135)<!-- prefix: "void stream_" --> · [Single-prompt stream](../apps/server/native_generate.cpp#L126)<!-- prefix: "void complet" --> · [Native dispatch](../apps/server/native_generate.cpp#L252)<!-- prefix: "void complet" -->

Buffering requires `--max-active 32`, `--batch-cuda-graphs`, and MTP disabled. Each of the 32 slots must hold a live, opted-in job whose first output callback has returned successfully. Each prompt must contain at least 32,768 IDs and use greedy selection, with no media, constraint, forced eager execution, or top-logit request. At least 25 mailboxes must have room when the scheduler takes its snapshot. It rechecks readiness and cancellation before dispatching each lane. [Cohort eligibility](../apps/server/batch_service.cpp#L253)<!-- prefix: "bool BatchSe" --> · [Job eligibility](../apps/server/batch_service.cpp#L827)<!-- prefix: "job-\u003ebuffer_" --> · [Greedy selection](../include/sglang/decoder.h#L41)<!-- prefix: "bool samples" -->

The mailbox holds at most two decode steps, including any step whose callback is running. A full mailbox blocks that lane and bounds lookahead to one K0 token beyond the outstanding callback. When the cohort falls back to ordinary scheduling, each lane drains its mailbox before decoding again. The decoder decides stop and length and retires the lane at the terminal step. The writer drains accepted output in FIFO order before serializing the terminal result, using the route's existing token, stop, metadata, and SSE formats. [Readiness](../apps/server/batch_service.cpp#L59)<!-- prefix: "bool ready(b" --> · [Publication and retirement](../apps/server/batch_service.cpp#L343)<!-- prefix: "void BatchSe" --> · [FIFO delivery](../apps/server/batch_service.cpp#L546)<!-- prefix: "const bool c" -->

A failed write or disconnect cancels the job and retires its decoder work before slot reuse. The job records whether steps have ever overlapped. That history determines [native abort delivery](native-abort.md#runtime-path) even after ordinary scheduling resumes. An already dispatched decoder step can finish, and publication suppresses its output if cancellation has won. [Disconnect retirement](../apps/server/batch_service.cpp#L518)<!-- prefix: "void BatchSe" --> · [Overlap history](../apps/server/batch_service.cpp#L360)<!-- prefix: "job.output_o" -->

## Verification

With the server running on the default port, request its model list.

```bash
curl --fail-with-body -i http://127.0.0.1:17384/v1/models
```

Require HTTP 200 and one card with the fields specified in [Model discovery](#model-discovery).

Run the [CPU reader and queue checks](../tests/prefix/README.md#cpu-reader-queue) with prefix reuse off and on. Check the reader limit and absolute deadline for partial headers and bodies. Check that large buffered requests reach the completion queue. Check overload, FIFO replacement after cancellation, and worker shutdown. Require health and readiness responses while partial reads or completions occupy their respective slots. With prefix reuse on, send a reset while a completion holds its slot. Require HTTP 409. Require health and readiness responses while reset acknowledgement is pending.

Run `bash tests/batch/run_service_mtp.sh "$PWD" "$PWD/artifacts/service-mtp-check"` from the repository root in the managed environment with `artifacts/` present. Require one admission callback before token delivery. [Callback assertions](../tests/batch/service_mtp.cpp#L37)<!-- prefix: "callbacks.on" -->

Run the host decode grace regression from the repository root in the default Linux Pixi environment. Create `artifacts/` before the run. The driver uses GNU linker wrapping and libstdc++ with a stub decoder.

```bash
bash tests/batch/run_service_decode_grace.sh "$PWD" "$PWD/artifacts/service-decode-grace-check"
```

With all outputs pending, require the worker to wait again after a spurious wake. Require 24 acknowledgements to remain in grace. Require 25 to dispatch those lanes before the timer expires. Release the last seven and require a separate dispatch. Require two ordered token IDs and a length finish for every item. Check that reset is rejected during streaming and succeeds when idle. [Threshold assertions](../tests/batch/service_decode_grace.cpp#L142)<!-- prefix: "fixture.rele" -->

For bounded decode output, block a writer after its first callback and verify one additional K0 step can run for its lane. Hold all writers until mailboxes are full and verify decoding waits. Release writers and check ordered IDs, stop and length retirement, and fallback when the cohort loses eligibility. Race native abort against normal terminal delivery with one claimed step and one queued step. When abort wins, check that the claimed callback completes, the queued step is dropped, and the slot becomes reusable. See the [CPU scheduler regression](../tests/batch/README.md).

The focused B200 replay checked greedy IDs on frozen histories for four full-length W5 prompts and 32 decode steps. Full W5 parity still requires 32 full-length prompts and 4,096 free-running output tokens per lane. CPU callback tests and modeled receipt delays leave socket-writer latency, GPU scheduler throughput, and end-to-end W5 speedup unmeasured.

Run the [streaming verification](development.md#streaming-verification) on a reserved B200. The [native prefill reset check](../tests/prefill/README.md) requires headers before prefill finishes. It resets after a traced chunk, checks retirement to zero request bytes, and verifies a replacement. [Reset assertions](../tests/prefill/run_native.py#L139)<!-- prefix: "def check_re" -->

Check wire silence with no decoder steps and with steps that [buffer tokens](lessons.md#l008--buffered-tokens-suppress-sse-keepalives). Require a comment after 15 seconds and measure TTFT at the first output ID frame. Exercise rejection before headers and generation failure after headers but before the first token. Require JSON status for rejection and an SSE error without `[DONE]` for the open stream.
