## Runtime path

For B200 target decode, see the [current grouped split route](singleton-gqa-decode.md#split-kv-target-attention). The packed K0 operator below requires at least two eligible decode lanes. ### Fused packed GQA

The fused step prepares Q and K, appends the new packed KV, and runs attention and output gating on the batch stream. The split uses whole 64-token chunks, with up to 16 partials per lane and query head. It preserves the original BF16 Q and expands raw E4M3 operands exactly to BF16. QK and PV use BF16 MMA with FP32 accumulation. PV rounds the probability times the relative V scale to BF16. Range checks cover operands, scale updates, and the merge. A flagged head replays attention in FP64. The fast path can still lose precision through cancellation. See [the regression inputs and results](lessons.md#l006--fp16-operand-loss-in-split-gqa). [Fused step](https://github.com/para1lel/sglang.cpp/blob/e1735c36c701581fd559bcaaa0d5adeb8c0337ad/src/text/gqa_decode_prepare.cu#L77)<!-- prefix: "cudaError_t " --> · [Split selection](../include/sglang/text/gqa_decode_split.cuh#L55)<!-- prefix: "__host__ __d" --> · [Merge](../include/sglang/text/gqa_decode_split.cuh#L125)<!-- prefix: "__device__ i" -->

The packed route uses two shared-memory stages. Each of four warps copies and consumes its own 16-token slice of the chunk. The payload copies use 16-byte `cp.async.cg` and zero-fill tokens past the visible tail. The scale copies use 8-byte `cp.async.ca` to give each warp disjoint scale writes. [Stage count](../src/text/gqa_decode_split.cu#L18)<!-- prefix: "constexpr in" --> · [Copy ownership](../src/text/gqa_decode_split.cu#L141)<!-- prefix: "__device__ v" --> · [Payload copy](../src/text/gqa_decode_split.cu#L101)<!-- prefix: "asm volatile" --> · [Tail predicate](../src/text/gqa_decode_split.cu#L155)<!-- prefix: "const bool v" --> · [Scale copy](../src/text/gqa_decode_split.cu#L173)<!-- prefix: "asm volatile" -->

Warp zero loads BF16 query fragments and their range flags into shared memory. The same CTA barrier publishes the query and page indices. During scoring, each of the four warps reads one 32-channel query group at a time. [Page indices](../src/text/gqa_decode_split.cu#L509)<!-- prefix: "for (int ind" --> · [Query publication](../src/text/gqa_decode_split.cu#L517)<!-- prefix: "__syncthread" --> · [Query group read](../src/text/gqa_decode_split.cu#L274)<!-- prefix: "const auto w" -->

In the two-stage loop, lanes wait for their copy groups and synchronize within the warp before they refill one stage and consume the other. All lanes drain their copies and synchronize across the CTA before they reuse shared memory for the merge. A final CTA barrier publishes the warp results before the block writes split partials. ### Packed FP8 projections

Packed eager and replay use the same FP8 projection dispatch and pass the bucket width as the row count. SM100 uses 8-, 16-, 32-, or 64-column activation tiles. The four-stage pipeline requires 5,120 input features, two targets with 17,408 output features each, and 16–32 rows. Packed MLP gate and up projections meet this shape at buckets 16, 24, and 32. The 16-row call uses a 16-column tile. Calls with 17–32 rows use a 32-column tile. [Packed MLP](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/src/text/decoder_graph_packed.cpp#L345)<!-- prefix: "check(text_f" --> · [Shape filter](../src/text/decode_proj_fp8.cu#L232)<!-- prefix: "bool use_mlp" --> · [Tile width](../src/text/decode_proj_fp8.cu#L369)<!-- prefix: "const int co" --> · [Pipeline dispatch](../src/text/decode_proj_fp8.cu#L386)<!-- prefix: "const bool s" -->

The FP8 copy and consumer warps wait on the same MMA completion phase. The copy warp refills shared memory and signals copy readiness. Consumer warps read TMEM and release the accumulator slot. The MMA warp waits for copy readiness and slot release before reuse. The four-stage pipeline halves the TMEM allocation and lowers dynamic shared memory at the cost of fewer stages for overlapping copies with compute. Its shared-memory request fits two CTAs per SM on B200. The split planner still uses the 64-column kernel and eight-stage footprint, preserving the split-K reduction order and BF16 rounding. #### Packed RMSNorm programmatic launch

Packed K0 uses one layer-input producer for GDN QKV and Z or for GQA Q/gate, K, and V. The first layer normalizes the embedding rows without a residual add. Later layers add the previous MLP output to the residual. ### Legacy wide eager decode

The former wide eager forward compacted long attention reads at widths above four. It covered 32,768–262,144 visible tokens, including the new token. The former operator was removed when grouped split GQA gained automatic [long draft dispatch](native-model-info.md#draft-attention). [Legacy dispatch](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/src/decoder_forward.cpp#L559)<!-- prefix: "const bool w" --> · [Position check](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/include/sglang/decoder_cuda.cuh#L235)<!-- prefix: "inline const" -->

Each layer appends the new KV before submitting that lane's grouped attention read. The tensor-core split requires at least five compacted reads and 16-byte-aligned K and V payloads for every lane in the group. The paired split handles groups of one through four or groups with an unaligned payload. Each split divides the visible sequence into 16 page-aligned partitions and clamps the final interval to the visible length. The paired split shares K and V across two query heads of one KV head. [Compaction](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/src/decoder_forward.cpp#L594)<!-- prefix: "if (!ordered" --> · [Split selection](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/include/sglang/text/mxfp8_gqa_decode.cuh#L386)<!-- prefix: "bool tensor " -->

Each tensor-core block serves one lane, one partition, and all six query heads of a KV head. Four warps process disjoint 16-token tiles. They decode visible E4M3 payloads and their E8M0 scales into BF16 and share K and V across the six heads. BF16 matrix instructions calculate QK scores and weighted V with FP32 accumulation. The softmax maximum, rescaling, and mass use FP32. Only the numerator multiplies BF16-rounded softmax weights by V. The block merges warp partials in FP32. ## Constraints and failure behavior

The legacy wide forward used row dispatch for out-of-window lanes. Exact policy, media, MTP, and prefill rows used separate routes. The old long primitive accepted one through 32 descriptors. [Historical eligibility](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/src/decoder_batch.cpp#L660)<!-- prefix: "const bool p" --> · [Former primitive](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/src/mxfp8_gqa.cu#L987)<!-- prefix: "cudaError_t " -->

The launcher checks the complete group before submission. An invalid count, null required pointer, unaligned scratch address, out-of-window position, or insufficient declared cache or page-table capacity returns `cudaErrorInvalidValue`. The caller supplies valid device page entries and enough scratch for each lane. The launcher stops at the first synchronous CUDA launch error. Earlier launches can still be in flight. The forward propagates the error through the batch execution path. [Validation and launch](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/include/sglang/text/mxfp8_gqa_decode.cuh#L380)<!-- prefix: "cudaError_t " --> · [Cache coverage](../include/sglang/text/gqa_verify_batch.h#L48)<!-- prefix: "inline bool " --> · [Forward error](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/src/decoder_forward.cpp#L630)<!-- prefix: "check(status" -->

The tensor-core split flags a query head if an input is nonfinite, a BF16 subnormal, or has magnitude above `2^30`. Visible nonfinite K or V flags all six query heads of that KV group. A nonzero decoded K or V magnitude below `2^-126` or above `2^30` also flags the group. The paired split flags nonfinite visible scores or partials and visible V scale bytes above 160. Both routes flag invalid merged maxima, mass, numerators, or BF16 results. A flagged head replays the visible tokens in order in FP64 from the original packed KV. Other heads keep their split results. [Query guard](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/include/sglang/text/mxfp8_gqa_wide_tc.cuh#L200)<!-- prefix: "const bool i" --> · [KV range guard](https://github.com/para1lel/sglang.cpp/blob/93648269d852e0fee78f7af4d1c3ffe4897aa361/include/sglang/text/mxfp8_gqa_wide_tc.cuh#L64)<!-- prefix: "const bool i" --> · [Merge guard](../src/mxfp8_gqa.cu#L705)<!-- prefix: "const bool i" --> · [Head replay](../src/mxfp8_gqa.cu#L716)<!-- prefix: "__device__ _" -->

Both splits change the reduction order. The tensor-core split also rounds numerator weights to BF16. Either choice can change BF16 attention output, logits, and generated IDs, including the greedy winner in a near tie.

### Packed route drift evidence

The historical packed comparison found nonzero KL and greedy divergence at widths above one, despite exact width-one results. Same-input FP64 probes and operator substitutions implicated FP8 projection reduction order and BF16 rounding of scaled softmax weights before the packed GQA value multiply.

The graph requirement is compare complete BF16 score rows bitwise across every eligible width and both low/high slot masks. Warmup must not consume a required mask. Full serving performance qualification remains open.
