## Where prefill breaks

`PrefillCudaGraphRunner` has its own startup token buckets. Admission tests slot and context limits, embedding overrides, supported output modes, and excessive padding. Target verify is rejected here. A full-capture configuration with chunked prefixes can add a key variant based on the number of prefix chunks needed. Breakable capture records graph segments separated by eager calls such as attention or Mamba hooks. The prefill runner can replay the transformer body and use live request metadata for the eager logits tail. It also has a separate Torch-compiled piecewise path. These are distinct from the fixed-width target-verify graph. ## What ports to the C++ runtime

1. **Prioritize exact five-row FP8 MLP projections.** The focused W1 trace had 51 five-row rounds and one two-row tail. The verifier used 1,208 ms of active GPU time and about 45 ms of GPU idle. Five-row MLP gate/up and down projections accounted for 475.49 ms. Halving that slice would save about 238 ms in the observed timeline if other costs held fixed. Verify projection outputs and exact native W1 IDs before timing any replacement. See `artifacts/mtp4-w1-focus/w1_cuda.sRwrkemt/REPORT.md`.
2. **Retain the five-row graph as a reference for correct replay.** At the reviewed base, `Decoder::Model::forward_verify` stages tokens and bindings in stable scratch, and `TargetVerification::graph_eligible` admits the two-row K1 layout. The five-row candidate demonstrated 50 completed CUPTI-correlated five-row replays on its first W1 and matched the golden transcript on all 48 W1 requests. Eager and capture-rejection fallbacks also preserved tokens. The pooled median of 1.8834 s was 2.15% lower than the published base's 1.9247 s. The difference fell below the predeclared 5% threshold and was inconclusive given the 10.44% block spread against a 3% limit. The candidate remains unshipped.
