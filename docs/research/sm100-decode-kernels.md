# SM100 decode and long prefill for Qwen3.8-27B-FP8

First batch the native FP8 projections across requests and pack their output channels at load time. In parallel, address W5 with long-context attention and a scheduler policy that lets early prompts finish. The pinned vLLM source selects CUTLASS for the checkpoint's block FP8 weights and packed Triton for FP32 GDN decode. The reconstructed W3–W6 settings predict TRTLLM-Gen GQA decode and FlashInfer FA2 prefill with 64-token kernel pages. Confirm the GQA backends and page size in a paired trace.

## Scope and observations

The [paired benchmark](../performance-comparison.md) used one B200, TP1, no MTP or prefix reuse, a 32,768-token budget and 32 service slots. The [checkpoint](checkpoint.md) has 16 GQA layers with 24 query heads and 4 KV heads of width 256. Its 48 GDN layers have 16 Q/K heads and 48 V heads of width 128. The FP8 weight blocks are 128×128. Native GQA uses per-32 E8M0 MXFP8 scales. vLLM uses plain E4M3 KV with unit per-tensor scales and BF16 queries.

## Paged GQA decode

The reconstructed vLLM settings predict TRTLLM-Gen decode on SM100 when the NVIDIA artifacts are accessible. The query head count is divisible by the KV head count. With one token and six Q heads per KV head, FlashInfer selects `SwapsMmaAbForGeneration`, Q tile 8. In the default BF16-Q/FP8-KV `separate_kv` mode, the mainloop transforms K and V separately. ## GDN recurrence and BF16 gates

**vLLM.** Ordinary decode uses a separate indexed causal convolution update with activation, then packed Triton recurrence. The recurrence reads packed QKV and B/A, normalizes Q and K, and computes `g=-exp(A_log)*softplus(a+dt_bias)` and `beta=sigmoid(b)`. It applies decay, delta update and the output reduction while updating the FP32 state. At widths 4 and 16 the packed kernel uses BK128, BV8, one warp and three stages. The separate gated RMSNorm consumes Z. CUDA fused GDN decode requires speculative configuration on this path and is downstream of convolution. BA is a single BF16 linear operation. The skinny-GEMM plan map covers SM121, so B200 delegates BA to PyTorch `linear`. Confirm its cuBLAS tactic from a trace. FlashInfer GDN prefill is a distinct path on SM100/CUDA ≥13 with K dimension 128. ## Scheduler and capture

vLLM schedules running requests before waiting requests. It allows partial prefill and spends the remaining token budget across requests in a shared forward. Its long-prefill cap defaults to zero. A new 32,768-token W5 prompt can use the full budget if the scheduler has assigned no tokens to other requests. The measured native scheduler shares the prefill budget across lanes and executes large prefill chunks as per-lane tiles. Its decode graph guard requires a pure decode step. Thus a step can spend the full budget without finishing any prompt. Native W5 completed 23 full prefill steps and recorded zero decode lanes before the first 90 s socket timeout. ## Implementation order

1. **W3/W4 — pack FP8 projections and batch the LM head.** Preserve FP32 scale arithmetic and pack only compatible 128-channel blocks. Share quantization across merged consumers and benchmark swapped M1–64 GEMM before adding new producer fusion. Capture 4, 16 and 32 lanes after the batched path works eagerly. Reaching reference projection-plus-quant sums would remove about 6.5 ms and 47.8 ms of kernel duration per W3 and W4 step. Check forced logits, Q/gate ordering, graph padding and small-M W1 throughput.
2. **W5 — test completion-oriented scheduling and improve long attention.** Replay W5 arrivals with bounded admission and older-prompt completion before changing capture. Reserve budget for ready decodes. Log per-lane prompt progress and attention time. Start attention tuning with a warp-specialized persistent causal tile and direct paged MXFP8 loading. Use a BF16 unpacked control to isolate scale staging. The 2.22× attention gap comes from W4. Measure W5 separately. Completing 32 equivalent steps by the timeout would require 1.39× the average prefill throughput observed over 23 steps. That estimate assumes equal work per step and is optimistic because attention work grows with context. Measure time to first token for each request. Record timeouts and decode starvation.
3. **W3/W4 and W5 decode — batch and split GQA.** Group six Q heads on each KV stream. Sweep context-based split count and merge online-softmax partials in FP32. Start with a global-memory merge, then test cluster reduction and tensor-core tiles. Reference sums suggest up to 4.6 and 16.4 ms of kernel duration opportunity. Preserve native group scales and benchmark append separately to expose conversion and bandwidth cost.
4. **W3/W4 — batch BA and fuse packed GDN work.** Use one BF16 `(M,5120)×(5120,96)` projection per layer. Use packed convolution output to drive integrated QK normalization, gates and the FP32 recurrence. Target the measured combined gap of 2.4 and 11.9 ms. Compare conv history and recurrence state over long forced continuations before fusing gated RMSNorm or considering BF16 state.

Keep existing model and cache contracts for the first experiments. The weakest speedup assumption is that native MXFP8 D256 tiles can approach the observed vLLM W4 attention time with extra group scaling. A simpler first experiment keeps native attention fixed and changes prompt ordering. It distinguishes early completion from increased prefill throughput.
