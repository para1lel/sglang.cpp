# Qwen3.8-27B-FP8 on two B200s

The checkpoint supports exact weight partitioning across two ranks. Each rank owns 12 query heads, two KV heads, eight GDN key heads, 24 GDN value heads and 8,704 FFN channels. Each produces a partial hidden row after attention and after the FFN. Sum both contributions before the next residual addition or normalization. Both ranks execute every text layer for the same requests.

Confidence is high in the tensor map below. The checkpoint headers and two pinned implementations establish its dimensions and ordering. Latency, kernel dispatch, graph capture and LMCache interoperability need native execution evidence. This report proposes implementation and acceptance checks. The [frozen performance contract](../performance.md#measurement) governs adoption.

## Checkpoint to rank-local operators

Shapes below use `[output,input]`. Rank `r ∈ {0,1}` takes `[r·n,(r+1)·n)` from each logical axis whose local length is `n`. A column-parallel linear slices output rows. A row-parallel linear slices input columns and produces a full-width partial sum. Apply each slice before native packing or transposition. The current loader packs GDN QKV with Z and the attention projections with each other. ## Execution and communication

**Native shape dependencies.** Keep checkpoint dimensions global. Pass local dimensions through allocations, tensor views, page tables, workspaces, graph buckets, dispatch and tensor-map construction. The current singleton decoder specializes widths 6144 and 17408. Grouped prefill recognizes whole-width gate/up and QKV banks. A whole-width kernel can silently miss a fast route, or address the wrong tile if forced on a local buffer. TP2 combines 7168 GQA projection rows, 8192 GDN QKV+Z rows and 17408 FFN gate+up rows. Preserve bank boundaries when dispatching these totals. The narrow GDN gate kernel explicitly requires 48 channels. Its rank-local SM100 route needs 24 valid channels per bank and safe tile tails. **Transport choice.** The project host reported eight B200 devices, driver 590.48.01, NV18 between every pair and peer read/write support in both directions. The default Pixi environment exposed CUDA 13.4.92 and NCCL 2.30.7 headers and `libnccl.so.2`. These observations establish available APIs and topology. They do not establish collective latency.

Start with one scheduler and a rank-owned device, stream, local memory and communicator. Resolve both physical UUIDs before allocation. Every step has one shared lane order, grant, position, reset and commit decision. Admit requests against both ranks' available memory. For single-process launch, initialize both ranks using `ncclCommInitAll`. Group matching per-device collectives when one host thread submits them. Execute collectives in identical order and count on both ranks, including graph capture and replay. Propagate rank failure to the whole step before publishing output. There are 128 hidden-row sum boundaries per target forward through 64 layers, plus two per executed full draft layer. Each sum covers `rows × 5120` values. A BF16 singleton row occupies 10,240 bytes. A BF16 partial rounded before summation can differ from a full FP32 accumulation rounded once. Compare against the established numerical contract. A two-peer CUDA implementation can exchange partials into persistent device buffers and sum on each rank. It needs peer enablement, producer and consumer stream ordering, safe reuse, graph support and error propagation. Compare NCCL with that option only if measured traces identify reduction time on the critical path. Match precision, shape, dependencies and warm replay when measuring.

## LMCache rank ownership

Baseline LMCache 0.5.8 uses one visible GPU per daemon, checks the IPC transfer UUID, and puts `kv_rank=0` in `ObjectKey`. Its SLC3 rectangle builder assumes four KV heads. Recommend one private daemon per rank, with distinct sockets and upstream ports. Bind each to its own physical UUID. Include world size, rank, model revision, layout version, family, prefix digest and salt in the compatibility identity. The transfer UUID identifies the device that owns an IPC handle. The logical rank identifies the checkpoint slice. Both must be checked. ### Selected native design with a full draft on rank 0

The mapping above describes the pinned references' sharded draft. The selected native design executes both target shards and runs the entire draft on rank 0. Its four draft KV heads require 2,112 bytes per cached draft token on rank 0 and zero on rank 1. Rank 0 owns the complete draft weights, state and workspaces. Keep the full BF16 target embedding and untied vocabulary head on rank 0 for local draft lookup and scoring. Preserve the full draft scoring representation for each enabled precision. All draft operators execute locally without collectives. Both ranks execute every target reduction in the same order. Deliver proposals and the target's commit, repair and stop decisions to both target workers. Apply draft rewind once on rank 0.

For this design, intersect both target endpoints at `P` and require draft coverage through `P−1` on rank 0 alone. Encode target and draft rank counts and head counts separately in cache compatibility and transfer geometry. Test rank 1 with target-only records and rank 0 with a missing draft tail. Budget the full draft memory on rank 0. Compare fixed-history proposals, verification and continuation with the full native draft control. Measure serial draft time on rank 0 in the paired K4 workload.

## Acceptance sequence

1. **Loader and projections.** Reassemble rank payloads and scale grids byte for byte against checkpoint coordinates. Include rank 1 at every bank boundary. Use distinct values across heads and scale blocks. Compare local intermediates and summed projections with independently dequantized reference operators. Retain errors before and after final BF16 rounding.
2. **Execution.** Compare TP1 and TP2 on identical token histories using the existing operator tolerances. Record full logits, winners, hidden rows, GDN state and all cache planes at matched boundaries. Compare each engine's free-running output separately. Exercise scalar, mixed prefill/decode, eager and replay, sampled and constrained paths. Cover vocabulary-boundary ties, graph reuse, sparse lanes, cancellation, admission failure and one-rank launch failure. Trace both UUIDs and matching collectives. [Operator qualification](../performance.md#operator-qualification)
3. **MTP.** Compare K0 with target-only controls, then K4 verifier results and continuation at zero, partial and full acceptance. Include rewinds, page crossings, partial chunks, inactive lanes and replacement. Check that both target workers commit identical decisions and positions. Check the draft frontier on rank 0 against the full-draft control. Apply existing draft-scoring and quality gates. [MTP qualification](../mtp.md#verification)
4. **LMCache.** Cold-store on both ranks and restore after compatible worker restart. Require byte equality for all four local KV planes, GDN state, hidden and residual. Exercise 31/32/33, 127/128/129 and 255/256/257 rows and the 8192 endpoint. Use distinct source and destination page mappings. Inject a wrong rank, swapped UUID, TP1 record, disjoint GDN endpoints and a failed transfer on one rank. Check joint fallback and next-token continuation. Verify draining, reset, reuse and logical counter accounting. [Cache verification](../prefix-cache.md#verification) · [Page remapping](../lessons.md#l002--remapped-kv-pages)
5. **Paired timing.** Require fresh TP2 runs on the same ordered pair of B200 UUIDs. Preserve MTP4, 32768 scheduled tokens, 16 active slots and per-GPU offered loads. W1–W5 consequently offer 2, 2, 8, 16 and 8 requests. Freeze request bytes, submit span, stops, client clock and admission rules. Retain each rank's effective precision and dispatch. Native uses MXFP8 and active direct LMCache. vLLM uses plain E4M3 KV and its local prefix cache, with KV transfer, KV offloading and CPU weight offload disabled. Verify effective worker settings. One warmup and one cold measured cohort per arm supply each point estimate. Require every row independently to satisfy `native makespan / vLLM makespan ≤ 1.10`. Retain the first miss, predecessor gates and existing wire, drain, counter and quality checks. [Scheduler policy](../performance.md#scheduler-and-reporting-policy) · [Named workloads](../performance.md#named-workloads) · [Measurement](../performance.md#measurement)
