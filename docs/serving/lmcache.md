# LMCache daemon

Run a dedicated LMCache 0.5.8 daemon for the native server on each node. The daemon moves GQA, GDN, and draft checkpoint data between native GPU allocations and one shared CPU L1 store. [Dependency pin](../../tools/lmcache/requirements.txt#L1)<!-- prefix: "lmcache==0.5" --> · [Upstream v0.5.8](https://github.com/LMCache/LMCache/commit/651617efcd556edf27387b646997869a2805fad2)

## Start the daemon

Install `tools/lmcache/requirements.txt` in a CUDA-capable Python environment. Set `LMCACHE_PYTHON` to its interpreter, or leave it unset to use `python3`. Run from the repository root under the same Linux user as the native server. Set `GPU_UUIDS` to one reserved physical GPU UUID for TP1 or a comma-separated pair for TP2 and `LMCACHE_SOCKET` to a private absolute socket path. [Version check](../../tools/lmcache/serve.sh#L69)<!-- prefix: "installed = " -->

```bash
export LMCACHE_PYTHON=/path/to/lmcache-environment/bin/python
CUDA_VISIBLE_DEVICES="${GPU_UUIDS:?set the reserved GPU UUIDs}" \
    bash tools/lmcache/serve.sh --socket "${LMCACHE_SOCKET:?set an absolute socket path}"
```

Expose the same physical UUID set to the daemon and native server. Set the server’s `CUDA_VISIBLE_DEVICES` in model rank order and use `--lmcache-socket "$LMCACHE_SOCKET"` with namespace `sglang`. Keep the daemon running across compatible worker restarts to retain checkpoints. Start a fresh store when needed and stop native workers before the daemon.

Use a socket parent owned by root or the service UID. A group- or world-writable parent must have the sticky bit. Startup and shutdown take a per-endpoint lock for up to two seconds. The service keeps the `0600` lock file in a `0700` directory named `.sglang-lmcache-locks-<euid>` under the socket parent. Leave it in place across restarts. If shutdown times out acquiring the lock, it closes the listener and leaves the socket path. On restart, the daemon can reclaim a stale socket owned by its UID. A live socket or a different type of file at that path prevents startup. [Lock acquisition](../../tools/lmcache/sglang_socket.py#L18)<!-- prefix: "def locked_d" --> · [Socket recovery](../../tools/lmcache/sglang_socket.py#L62)<!-- prefix: "def remove_s" -->

| --- | --- |
| `--socket PATH` | `$XDG_RUNTIME_DIR/sglang-lmcache.sock` if that variable is absolute, otherwise `/tmp/sglang-lmcache-<euid>.sock`. Use an absolute path shorter than 108 bytes under an existing directory. |
| `--namespace NAME` | `sglang`. The module serves one namespace. The client and daemon must use the same value. |
| `--memory-gib N` | `16`. Sets the initial and maximum CPU L1 capacity in GiB. Use a finite positive value. The paired drivers use 64 GiB for TP1 and 128 GiB for TP2. |

The launcher selects `--supported-transfer-mode lmcache_driven` and sets `--l1-init-size-gb` and `--l1-size-gb` for the dedicated DRAM L1 with LRU eviction. Before the Unix socket opens, LMCache allocates and registers L1 memory, and the daemon initializes the CUDA context and PyTorch stream pool on each visible GPU. Initialization failure aborts startup before the ready log. Wait for that log before starting native workers. The upstream ZeroMQ listener on loopback TCP checks the generated API key. The native Unix socket uses mode `0600` and accepts peers with the daemon's effective UID. Same-UID peers with socket access and the configured namespace can look up, transfer, and delete records or clear the entire store. Use a separate service UID, private socket directory, and dedicated daemon for each trust domain. ## Native transport

Run the daemon and native server from the same checkout. The native handshake requires `0.5.8+native-v3` for the compact SLC3 protocol. The application sends one four-plane MXFP8 view per GQA or draft family, with row bounds and chunk digests. A GDN record identifies one exact endpoint and describes four state spans. Native keeps the GPU allocations and readiness event alive until the daemon releases them. The application allocates no host buffer for the cache payload. [Handshake](../../src/runtime/cache/lmcache_client.cpp#L27)<!-- prefix: "constexpr st" --> · [MXFP8 view](../../src/runtime/cache/lmcache_client.cpp#L267)<!-- prefix: "void append_" --> · [GDN view](../../src/runtime/cache/lmcache_client.cpp#L290)<!-- prefix: "void append_" --> · [Release reply](../../tools/lmcache/sglang_lmcache.py#L255)<!-- prefix: "def release_" -->

The daemon uses the request’s 16-byte physical GPU UUID to select the CUDA context, transfer stream, readiness event and imported mappings. Device order can differ. An unknown UUID is rejected before L1 access or ARM. It waits for GPU readiness before copying. When CUDA supports batched copies, the daemon uses a pitched copy batch for stores and for restores with disjoint destinations. Otherwise it uses LMCache's object-group transfer. A batched submission error propagates. The daemon synchronizes the transfer stream and closes imported mappings before releasing the views. [Device and copy dispatch](../../tools/lmcache/sglang_gpu_transfer.py#L284)<!-- prefix: "def run(self" --> · [UUID validation before admission](../../tools/lmcache/sglang_lmcache.py#L701)<!-- prefix: "self.server." --> · [Allocation ownership](../../tools/lmcache/sglang_gpu_transfer.py#L317)<!-- prefix: "def map_allo" -->

The daemon deadline covers command receipt and the client's ARM acknowledgement. It still applies to unarmed reset and delete requests. An armed GPU transfer can finish beyond that deadline. The daemon still checks for disconnects before changing records and releases the views after device synchronization and unmapping. [Deadline check](../../tools/lmcache/sglang_lmcache.py#L200)<!-- prefix: "def check_mu" --> · [ARM acknowledgement](../../tools/lmcache/sglang_lmcache.py#L248)<!-- prefix: "def arm(self" -->

The daemon pins L1 read and write reservations through GPU transfer and reservation cleanup. These pins protect the records from eviction after the ordinary reservation timeout expires. The daemon refuses forced clear or delete while a reservation is active. [Reservation pins](../../tools/lmcache/sglang_lmcache.py#L281)<!-- prefix: "class DmaRes" --> · [Forced reclaim](../../tools/lmcache/sglang_lmcache.py#L313)<!-- prefix: "def reclaim(" -->

The public Qwen3.8-27B B200 recipe specifies MTP3 and LMCache 0.5.1. With the repository's pinned vLLM and LMCache 0.5.8, the resolver selects the wheel's `LMCacheMPConnector` when `LMCACHE_USE_UPSTREAM_MP` is unset and the import succeeds. Its `wait_for_save()` records a CUDA event and submits stores asynchronously. vLLM can finish the request while a store is pending and retains its blocks until `finished_sending`. The stock defaults store complete prompt chunks. Native runs MTP4 in the matched benchmark and submits a checkpoint every 8,192 processed target tokens and at successful request end. Native lookup uses [exact GDN endpoints and independent GQA coverage](../prefix-cache.md#checkpoint-compatibility-and-resume). ## Ranked TP2 transport

Both ranks use one absolute socket and the `sglang` namespace. The daemon shares one CPU L1 across the devices. Check readiness and reset through the shared connection. Preserve both physical UUIDs in process and device receipts. [Shared client](../../src/runtime/cache/lmcache_group.cpp#L27)<!-- prefix: "LmCacheGroup" --> · [Single reset](../../src/runtime/cache/lmcache_group.cpp#L192)<!-- prefix: "void LmCache" --> · [Former two-daemon procedure](https://github.com/para1lel/sglang.cpp/blob/57ac5fbbdf20a5a80c5bc079b49073a44c06680f/docs/serving/lmcache.md#ranked-tp2-transport)

Ranked `READY` appends each rank’s raw 16-byte physical GPU UUID after the namespace. A missing UUID returns status `3`, leaves `lmcache_available` false, and sends generation through cold prefill. While LMCache is unavailable, later requests recheck readiness before ranked lookup. An empty UUID list still returns the existing version reply. [Wire request](../../src/runtime/cache/lmcache_client.cpp#L447)<!-- prefix: "bool LmCache" --> · [Daemon validation](../../tools/lmcache/sglang_lmcache.py#L672)<!-- prefix: "def ready(se" --> · [Readiness recheck](../../apps/server/batch_cache.cpp#L327)<!-- prefix: "bool ready_f" -->

Ranked clients select the operations `lookup_prefix_detail`, `retrieve_v4`, and `store_v4`. A `retrieve_v4` or `store_v4` frame matches the SLC3 frame and inserts the KV head count after the end row bound of each nonempty MXFP8 section. A daemon without these operations rejects the request, so the client reports an error instead of a partial restore. [Operations](../../src/runtime/cache/lmcache_client.cpp#L46)<!-- prefix: "lookup_prefi" --> · [KV head count](../../src/runtime/cache/lmcache_client.cpp#L282)<!-- prefix: "if (v4) appe" -->

Ranked records live in per-rank key domains that name the world size, rank, KV and GDN head counts, and draft or target role. The TP1 domain stays unchanged, so TP1 and TP2 records do not mix. [Key domain](../../src/runtime/cache/prefix_payload.cpp#L63)<!-- prefix: "std::string " -->

A ranked lookup reads matched lengths and endpoint inventory for each rank key domain. The group takes the minimum matched GQA and GDN lengths. It picks the largest usable GDN endpoint present on every rank with draft eligibility on rank 0 when a draft is requested. A truncated inventory reply is refused. [Composite lookup](../../src/runtime/cache/lmcache_group.cpp#L39)<!-- prefix: "PrefixCacheR" -->

A ranked restore drives one transfer per rank and reports completion only when every rank completes. Incomplete transfer resets the partial restore on both ranks before cold prefill. The shared L1 stores immutable rank shards independently. A checkpoint counts as acknowledged only when both rank stores succeed. A missing shard leaves the other shard available for future lookups. Byte receipts sum across ranks, and restored tokens are counted once. The serving cache service constructs the ranked group when serving under two ranks. ## Cache identity and vendor isolation

Each request's key domain embeds a checkpoint identity: a SHA-256 over `config.json`, the safetensors index, and every safetensors file's stat data. [Checkpoint identity](../../src/runtime/server/cache_identity.cpp#L38)<!-- prefix: "std::string " --> · [Request domain](../../apps/server/detail/batch_service_cache.cpp#L24)<!-- prefix: "std::string " -->

Current native ranked keys use the checkpoint identity without a recurrence tag. [Frozen vendor recurrence tag behavior](https://github.com/para1lel/sglang.cpp/blob/a5974ba4eb99bd8e8f890c2e7262a27dbc3aace1/docs/serving/lmcache.md#cache-identity-and-vendor-isolation)

If an older vendor opt-in wrote untagged records to persistent daemons, drain and reset the old store or start with a fresh namespace before reusing native keys. A per-request cache salt leaves the namespace unchanged. [Reset controls](../prefix-cache.md#native-http-controls)

## Standalone verification

The B200 standalone proof stored and retrieved all three payload families into separate GPU allocations. It compared the region contents and untouched guards byte for byte. The GQA record held 459 rows across 16 layers, the draft record held 458 rows, and a single GDN span crossed a 64 MiB pinning boundary. This proof covers the daemon transport. Check worker restart, serving correctness, and request performance separately with the integrated implementation.
