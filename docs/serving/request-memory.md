# Request memory and GPU pools

Each rank starts one device arena. The default `gpu_memory_utilization` is `0.88`. The arena caps the startup budget at that fraction of total device memory and leaves up to 2 GiB of free memory for the CUDA driver. The budget includes startup weights and other framework-owned device storage. The decoder commits separate general and exportable cache backing before serving. ## Peer draft repair

A resident B200 TP2 batch can stage draft repair on rank 1 for eight or sixteen complete, unconstrained greedy text K4 lanes. Each lane needs more than five remaining tokens and ordinary in-range positions. The batch needs eager execution, packed activations, no output callback, bidirectional CUDA peer access, and room above both shared reserves. The batch owner reuses the same sixteen-lane allocation for either width, with 117,196,544 bytes of rank-1 weights and scratch and 262,144 bytes of rank-0 return storage. A return copies 131,072 bytes for eight lanes or 262,144 for sixteen. Missing support or insufficient memory uses ordinary rank-0 repair. Peer repair requires matching MNNVL reductions throughout the verifier. At 40 or 80 rows, 127 reductions use fused one shot and the final reduction uses the ordinary transport for that width, or all 128 use that ordinary transport. The ordinary route is one shot at 40 rows and two shot at 80. The rank-1 auxiliary stream waits for the verifier rows and projects provisional K/V while rank 0 scores the packed rows with the [certified head](../native-model-info.md#certified-tensor-core-target-head). A packed-score decline discards the return. Ordinary commit must authorize all 32 or 64 rows with matching request, token, position, rotary position, and normalized input at the live prefix. Rank 0 then applies rotary and appends to its original MXFP8 pages. Partial acceptance, stops, and clean declines use ordinary repair after draining provisional work. Rank 1 owns only provisional draft buffers.
