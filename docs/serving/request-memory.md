# Request memory and GPU pools

Each rank starts one device arena. The default `gpu_memory_utilization` is `0.88`. The arena caps the startup budget at that fraction of total device memory and leaves up to 2 GiB of free memory for the CUDA driver. The budget includes startup weights and other framework-owned device storage. The decoder commits separate general and exportable cache backing before serving. ## Per-rank resident admission

With resident admission enabled, the batch measures each participating rank’s free general arena after shared setup, deducts the shared workspace allowance, and applies the configured `resident_memory_limit` to each rank. Charge each slot on the device that owns its state. TP1 counts full state on one device. TP2 counts each rank’s local KV geometry, GDN and replay state, and target, draft and verification workspaces. The prefix pool budgets pooled KV separately. Extra primary-side request storage is charged on rank 0. [Capacity measurement](../../src/runtime/cache/kv_residency_policy.cpp#L21)<!-- prefix: "void KvResid" --> · [Rank charges](../../src/runtime/execution/decoder_batch_state.cpp#L113)<!-- prefix: "std::array<s" -->

Admission tests the output limit against every rank’s measured capacity. For an implicit budget, it selects the largest output count that fits all ranks. An explicit budget must fit in full. It then tests that charge against current free space, live reservations and retired ranges on each rank. A fixed-capacity refusal is terminal. A temporary shortage on either rank is retryable and preserves the chosen output budget. Both ranks must pass before the lane is initialized. [Output limit](../../src/runtime/model/qwen_request.cpp#L127)<!-- prefix: "int limit_re" --> · [Live headroom](../../src/runtime/model/qwen_request.cpp#L156)<!-- prefix: "bool has_res" -->

In a scoped B200 witness with 64 prompt tokens and 12 requested outputs, TP2 produced the same K0 and K4 control IDs in both revisions. A 144 MiB per-rank limit admitted one local K0 request that the parent refused. At 272 MiB the revised policy admitted both K0 lanes concurrently. The parent needed a lane retirement and retry. Peer pressure applied after batch setup caused a retryable K4 refusal. Releasing it recovered the same output. Peer pressure present at batch setup caused a terminal K0 refusal. The TP1 control IDs matched. Verify implicit clipping separately by checking the largest fitting budget and the next higher budget. Cover temporary shortage independently with live reservations and unreleased retirements.

## Rank-local draft storage

Each TP2 rank holds its own draft shard, KV page map and request workspace. Draft seed, proposal and repair use device-local state. The peer gets the recurrent input needed for its shard as part of the ordered rank wave. Target-forward replay leaves these draft stages outside capture.
