# Retired request allocations

A [resident-limited batch](../batch-graphs.md#resident-memory-admission) can reuse same-size device blocks after the target and draft finish using them. With CUDA memory-pool support, the reuse cache holds up to 3 GiB and 1,024 blocks. A separate worker frees blocks on a nonblocking stream. Its queue accepts up to 1,024 outstanding blocks and normally up to 3 GiB. When the last checkpoint owner releases a detached block, the worker can accept it above the byte limit. If the queue declines it, the owner frees it on the per-thread stream and waits for completion. Without memory-pool support, the reuse cache holds up to 768 MiB and 384 blocks. `request_device_allocation_bytes()` counts active request storage. When CUDA reports that asynchronous release is unsupported, the owner frees the fenced allocation with `cudaFree`. Other CUDA errors propagate to the existing cleanup path. [Release fallback](../../include/sglang/runtime/backend/cuda_resources.h#L45)<!-- prefix: "inline cudaE" -->

Pending releases count against the fixed request limit until the release stream completes. Retired blocks that an exported checkpoint still owns also count against that limit. The recycling path cannot reuse them. Admission charges each block once as its ownership moves from the request to the exported view or release queue. Admission can drain pending releases and clear reusable blocks to preserve the shared reserve or fit the limit, then rechecks both before allocating. After CUDA allocation failure, the allocator can trim and retry once if the device has room above the shared reserve. The HTTP batch worker trims after five seconds waiting with no jobs. C++ callers can call `release_retired_allocations()`. ## Peer draft repair

A resident B200 TP2 batch can stage draft repair on rank 1 for 16 complete, unconstrained, greedy text K4 lanes. Each lane needs more than five remaining tokens and ordinary in-range positions. The batch needs eager execution, packed activations, no output callback, bidirectional CUDA peer access, and enough free memory to keep both shared reserves. The batch owner reserves 117,196,544 bytes of rank-1 weights and scratch and 262,144 bytes of rank-0 return storage. Missing support or insufficient memory uses ordinary rank-0 repair. When all 80-row verifier reductions use MNNVL two shot, an auxiliary rank-1 stream waits for the verifier rows and projects provisional draft K/V while rank 0 scores two 40-row groups. A packed-score decline discards the return. Ordinary commit must authorize all 64 rows with matching request, token, position, rotary position, and normalized input at the live prefix. Rank 0 then applies rotary and appends to its existing MXFP8 pages. Partial acceptance, stops, or a clean decline drain provisional work and use ordinary repair. Rank 1 holds no persistent draft state.
