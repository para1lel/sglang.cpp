# Retired request allocations

A [resident-limited batch](../batch-graphs.md#resident-memory-admission) can reuse same-size device blocks after the target and draft finish using them. With CUDA memory-pool support, the reuse cache holds up to 3 GiB and 1,024 blocks. Without that support, it holds up to 768 MiB and 384 blocks. `request_device_allocation_bytes()` counts active request storage. Each rank allocates exportable request blocks with legacy `cudaMalloc` on its own GPU. The [IPC lease](lmcache.md#native-transport) keeps exported storage alive through importer unmapping. After the last export owner drops a detached block, the owning GPU's release worker can accept it. The TP2 peer uses this worker for checkpoint exports and keeps resident reuse disabled. With memory-pool support, each rank's release queue holds up to 3 GiB and 1,024 blocks. The worker batches `cudaFreeAsync` calls on a nonblocking stream and fences that same stream before clearing the pending charge. A block that cannot fit, or has no release queue, goes to the releasing thread’s per-thread stream. That thread fences its stream. Only `cudaErrorNotSupported` with no other pending CUDA error permits legacy `cudaFree`. An IPC-held block counts once after retirement and stays unavailable for reuse. Queued releases remain charged until completion. Admission can trim reusable blocks and drain pending releases, then rechecks the fixed limit and shared reserve. An allocation OOM can trigger one retry after trimming if memory remains above the reserve. The HTTP worker trims after five seconds with no jobs. C++ callers can call `release_retired_allocations()`. ## Peer draft repair

A resident B200 TP2 batch can stage draft repair on rank 1 for eight or sixteen complete, unconstrained greedy text K4 lanes. Each lane needs more than five remaining tokens and ordinary in-range positions. The batch needs eager execution, packed activations, no output callback, bidirectional CUDA peer access, and room above both shared reserves. The batch owner reuses the same sixteen-lane allocation for either width, with 117,196,544 bytes of rank-1 weights and scratch and 262,144 bytes of rank-0 return storage. A return copies 131,072 bytes for eight lanes or 262,144 for sixteen. Missing support or insufficient memory uses ordinary rank-0 repair. Peer repair requires matching MNNVL reductions throughout the verifier. At 40 or 80 rows, 127 reductions use fused one shot and the final reduction uses the ordinary transport for that width, or all 128 use that ordinary transport. The ordinary route is one shot at 40 rows and two shot at 80. The rank-1 auxiliary stream waits for the verifier rows and projects provisional K/V while rank 0 scores the packed rows with the [certified head](../native-model-info.md#certified-tensor-core-target-head). A packed-score decline discards the return. Ordinary commit must authorize all 32 or 64 rows with matching request, token, position, rotary position, and normalized input at the live prefix. Rank 0 then applies rotary and appends to its original MXFP8 pages. Partial acceptance, stops, and clean declines use ordinary repair after draining provisional work. Rank 1 owns only provisional draft buffers.
